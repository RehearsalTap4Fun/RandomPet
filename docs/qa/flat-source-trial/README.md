# 像素首批：3 张源图与消费端对照

## 范围与状态

第①阶段仅制作橘白微张嘴主体、龙角、焰尾三张平涂候选。用户已确认“认可 C 列，进入第二阶段组合验证（推荐）”，精确范围与文件指纹见 `consumer/approval.json`。第②阶段（鳍耳、小狮鬃、小尖牙、短腿适配）结果见 `stage2/index.html` 与 `stage2/README.md`，另行验收。

正式对照入口：`consumer/index.html`；总览：`consumer/comparison.png`；工程证据：`consumer/report.json`。

`index.html` 是获取 Nutri 代码前的本地临时预检，处理参数不同，仅作辅助。不要把它当成消费端结果。

## 实际使用的消费端

- 仓库：`git@github.com:RehearsalTap4Fun/Nutri.git`
- 提交：`b7addf5914c18d8904103ba87576b196f3f75d9b`
- 原始脚本：`scripts/pixelCat.ts`，未经逻辑修改，通过 esbuild 编译后执行。
- 合成：原始 `renderOps` + `composeSprite`。脚本自带的六组预览不包含新增的橘白微张嘴主体，因此使用四组定向样本调用同一运行时函数。
- 读取当前 RandomPet 的正式 catalog 与资源。新三张走 `--source`，其他 41 张回退旧素材；没有替换任何生产资源。

## 对照设计

| 列 | 输入 | 处理 |
|---|---|---|
| A | 毛绒源 | Nutri 毛绒模式：主体 14 色、部件 8 色，多级去纹理 |
| B | 毛绒最终坐标源 | Nutri 平涂模式：主体 12 色、部件 6 色，较轻滤波 |
| C | 平涂候选源 | 与 B 相同的平涂模式 |

A/C 比较实际路线；B/C 控制处理参数，观察源图差异。三列都生成基础、龙角、焰尾、龙角＋焰尾四组，共 12 张。像素原图 64×64，网页提供 64、128、256 整数倍显示及深浅底。

- Nutri 代码、原始 manifest、源图与输出图层的文件指纹见报告。
- 龙角修正前后，12 张合成中仅 C 列的龙角、龙角＋焰尾两张发生变化。
- 验收页 36 个图片元素全部加载成功，无页面脚本错误；深浅背景切换已检查。

## 目视判断与限制

- 平涂候选的脸、胸口和焰尾结构更清楚；单纯把毛绒源改走轻滤波，不能达到相同效果。
- 首版龙角朝外且偏低，被耳朵/头顶遮挡。第二版改为更直立的轮廓，提高双角在 64px 下的露出。修正前对照与报告在 `consumer/before-horn-fix/`。
- 这次修正有意调整像素部件形状，因此不满足“严格保留旧部件轮廓”的假设。长期应为像素版单独保存定位、轮廓和遮挡配置。
- 主体局部仍有渐变，未严格实现每种材质最多三种纯色；生成源尚不能视为标准化平涂母版。
- 本批未覆盖换耳、前胸鬃毛、微小表情、其他花纹与新体型，不能推导这些组合已通过。
- 当前建议：确认首批风格后进入第②阶段小范围组合验证，不开始批量重画 44 张。

## 复现

先将上述 Nutri 提交检出到 `.worktrees/nutri-pixel-reference`，或通过 `NUTRI_DIR` 指定本地路径，然后在本仓库执行：

```powershell
node scripts/review-pixel-consumer.mjs
```

该命令仅重建 `docs/qa/flat-source-trial/consumer/{plush,control,flat}` 内的像素图；在 Nutri 参考副本内生成临时编译文件，不修改其受 Git 跟踪的代码。需要本仓库现有 sharp、esbuild；不必安装 Nutri 的全部依赖。

源图生成使用内置 imagegen，原始提示词、修正提示词和尝试记录见 `docs/art/flat-source-trial/generation-batch0.json`。纯色底与自动抠图属于已确认试验流程。
