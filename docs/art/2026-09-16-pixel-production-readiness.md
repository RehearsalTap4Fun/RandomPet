## 已确认的生产决策

用户原话：“毛绒的可先保持目前的规模，后续扩展按像素为准”。

- 毛绒版保留现有资源规模与可用组合，后续新增性状不要求同步补齐毛绒资源。
- 后续体型、眼型／表情、异化资源以像素版为主要扩展方向，继续采用少量多批次的组合验证。
- 沿用已确定的长期目标：基因／性状规则、表现型、美术分离。两种风格共享性状语义，各自声明资源覆盖范围。
- 新增像素性状不能假定毛绒版也支持；风格切换须检查资源覆盖，保留已有毛绒形象的回放能力。

## 实施前确认的差距（保留设计依据）

| 位置 | 当前实现 | 正式化需要解决的问题 |
|---|---|---|
| generator-core/feline-combination | selections 含花纹、表情和五个异化位，没有 body | 正式表现型需要表示体型，并为旧数据提供确定的默认体型 |
| generator-core/sampleSlot | 随机流输入含 catalogVersion | 新美术版本不应改变同一只猫的性状；保留旧生成算法，通过适配层提取表现型 |
| asset-catalog/feline-combination-catalog | 资源与画布严格固定为 1254×1254 | 像素目录需要自己的尺寸、资源摘要和版本，不直接放宽旧目录并改变其含义 |
| renderer-canvas/feline-body-study | 短腿试验 profile 已包含定位和遮挡，但只支持固定体型／花纹／表情 | 提炼经验证的 profile 字段，形成正式的美术映射契约 |
| Nutri/scripts/pixelCat.ts | 部件变换与擦除模板由脚本内常量提供 | 应读取发布包中的体型美术配置，避免复制几何后两边失配 |
| Nutri/core/pixelcat.ts | CatSpec 无体型；renderOps 将 neck 绘制在 frame | 需要按 profile 确定层级，而不是把所有颈部性状固定为同一层 |
| Nutri/ui/PixelCat.tsx | 使用全局尺寸和 CLEAR_POLYGONS；缓存按性状生成键 | 缓存还应区分体型、美术版本及其资源修订，读取对应的擦除区域 |

## 已采用的结构

1. **性状规则／未来基因层**：负责抽取、成长或继承规则，输出表现型。现有 seed/rolls 生成保留兼容；本轮不补育种系统。
2. **表现型**：只表达体型、花纹、表情、异化选择，不包含 PNG 路径、缩放比例或遮罩。
3. **美术配置与渲染**：表现型结合 styleId 与 artVersion，得到资源、层级、定位、擦除和遮挡。像素与毛绒各自维护资源覆盖情况。

新旧边界应采用显式适配，而不是通过修改旧 catalogVersion 触发重抽。已有猫的已解析性状应被保留；支持集合、可生成集合与已验收组合也应分别表达。

## 首个正式包的建议范围

- 仅收录经明确验收的橘白主体与异化组合；标准体型和短腿体型分别登记覆盖范围。
- 原生 64px、128px 整数放大；提供可复现转换记录和资源摘要。
- 纳入体型映射、部件定位、前胸鬃毛层级、脸部遮罩和换尾区域。
- 不为缺失的平涂资源默默拼入毛绒部件。正式包应明确报告不支持的组合，由上层选择完整的兼容版本或限定新生候选集合。
- 旧存档与旧美术包继续可回放。是否让现有 Nutri 用户自动切换美术版本，应作为正式接入范围的一部分明确。

## 两项决策进度

1. **已确认**：毛绒版保持现有规模，后续扩展以像素版为准。
2. **已确认**：用户回复“ok”，采用推荐范围：先在 QMonsterCreator 完成表现型、美术配置、像素发布包与预览／导出，并提供 Nutri 接入契约和验证样例；随后单独推进 Nutri 消费端适配。

## 后续实施验收标准

- 同一份表现型切换已有美术版本时，体型／花纹／表情／异化 ID 不发生变化。
- 旧保存数据与旧随机生成结果不因新美术目录增加而漂移。
- 不支持的体型或资源组合得到明确诊断，不能用任意图片顶替。
- 预览、导出与消费端读取同一份层级／遮罩配置；新版本参与缓存标识。
- 保留首批与第二阶段的可复现组合证据，按实际支持范围执行回归。
