# QMonster v0.8 Canonical Species Rig Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a v0.8 feline generator whose complete anatomy comes from one canonical full-creature bundle and whose fourteen independently rare traits can only render inside contract-owned regions through one production renderer.

**Architecture:** Add a versioned `SpeciesRigContract` and a v0.8-only part composition mode. The generator reuses deterministic 8:4:1 part selection, while the renderer draws one complete AnatomyBundle at identity transform and clips every phenotype layer to a rig-owned mask. The creator, catalog report, CLI review batch, and incubator adapter all consume the same catalog and `renderMonster` entrypoint; v0.1–v0.7 remain read-only and cannot be used as a v0.8 fallback.

**Tech Stack:** TypeScript 7, Zod 4, Vitest 4, React 19, Canvas 2D, Sharp 0.35, Vite 8, Playwright 1.62, PNG/WebP assets.

**Spec:** `docs/superpowers/specs/2026-09-08-qmonster-v0.8-canonical-species-rig-design.md`

## Global Constraints

- Target catalog, renderer, and spec versions are exactly `0.8.0`, `0.8.0`, and `0.3.0`.
- The first release contains only `archetypeId: feline`, `rigId: feline-sit`, and `speciesRigId: feline-sit-v1`.
- One AnatomyBundle structural asset contains the complete head, neck, torso, four limbs, tail root, and one natural cat tail; v0.8 never renders structural connectors or bridges.
- Every visual slot has exactly `8 N / 4 R / 1 L` reachable traits and draws tiers with `PART_RARITY_WEIGHTS = { N: 8, R: 4, L: 1 }`.
- All v0.8 render assets are 2048×2048 RGBA images on the canonical canvas; no trim, content-centering, translation, rotation, scaling, or mirroring is permitted.
- Every non-structural pixel is clipped by an owner region from the same canonical master; material, pattern, and color visible pixels outside the body owner mask must equal zero.
- The creator, report, acceptance page, and batch command call `renderMonster`; no second compositor or hardcoded slot-position table may be added.
- Existing v0.1–v0.7 catalogs, assets, specs, renderers, and imports remain behaviorally unchanged.
- Preserve every pre-existing modified or untracked v0.6/v0.7 file in the current worktree. Stage only the exact files listed by each task; never use broad `git add packages` or `git add .`.
- Existing v0.7 source PNGs are concept references only. Do not delete or overwrite them, and do not copy their structural pixels into v0.8 production assets.
- Automated checks decide only resource and geometry validity. Generate the final ten-image review batch once; do not subjectively reroll or regenerate it before user review.
