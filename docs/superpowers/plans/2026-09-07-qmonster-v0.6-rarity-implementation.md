# QMonster v0.6 Rarity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make v0.6 feline collections visibly and deterministically express Normal, Rare, and Legendary rarity without reintroducing composited body parts.

**Architecture:** Rarity belongs first to an entire `AnatomyBundle`; generation rolls an available tier at 70/25/5 and then weighted-selects an unlocked compatible Bundle. A catalog-derived `collectionRarity` takes the highest tier among the selected Bundle, visual parts, and applied modifiers, so later local trait pools can contribute without a schema migration. The Creator and incubator adapter consume that same derived value.

**Tech Stack:** TypeScript, Zod catalog validation, Vitest, React, existing v0.6 JSON catalog/source manifest.

**Spec:** Chat-approved 2026-09-07 rarity design: N/R/L = 70/25/5; current full-cat bundles use five N, two R, and one L source silhouettes; mutations/aberrations can raise the collection tier; no new image generation or automatic visual retry.

## Global Constraints

- Keep v0.6 as a single full AnatomyBundle structural draw; do not add runtime connectors or independent structural composition.
- Preserve legacy catalog behavior and the user’s pre-existing uncommitted worktree changes.
- Existing sources are classified only: no raster regeneration, auto visual scoring, or retry loop.
- Locked structural selections override the random rarity tier only when they leave one compatible Bundle tier.

```ts
export function deriveCollectionRarity(spec: MonsterSpec, catalog: Catalog): Rarity {
  return highestRarity([
    catalog.anatomyBundles?.find(item => item.id === spec.anatomyBundleId)?.rarity,
    ...Object.values(spec.visualSlots).map(selection => partById.get(selection.partId)?.rarity),
    spec.mutation && modifierById.get(spec.mutation.id)?.rarity,
    ...spec.aberrations.map(application => modifierById.get(application.id)?.rarity),
  ])
}
```
