# QMonster v0.4 Single-Face Hierarchy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship immutable QMonster catalog/renderer `0.4.0` with a complete-face contract, a separate non-facial intensity budget, three single-pass reworked art assets, and one final random batch marked for user review.

**Architecture:** Extend the existing catalog policy instead of adding a new slot or genome shape. Generator-core enforces both strong-feature budgets, renderer-canvas measures `oralDetail` with the existing face-safe-zone machinery, and a dedicated release assembler carries forward immutable `0.3.0` structural assets while replacing only the three approved high-risk non-structural parts. The creator defaults to `0.4.0` but retains exact loaders and rendering for `0.1.0`–`0.3.0`.

**Tech Stack:** TypeScript 7, Zod 4, Vitest 4, React 19, Canvas 2D, Playwright 1.62, Sharp 0.35, Codex built-in image generation.

**Spec:** `docs/superpowers/specs/2026-09-01-qmonster-v0.4-single-face-hierarchy-design.md`

## Global Constraints

- Keep all 14 `VISUAL_SLOT_IDS`; do not change `MonsterSpec.schemaVersion` or `MonsterGenome.genomeVersion` from `0.1.0`.
- Add exact `catalogVersion: "0.4.0"` and `rendererVersion: "0.4.0"`; preserve every committed `0.3.0` catalog, asset, audit, review, and acceptance byte.
- Automatic generation must satisfy `maxStrongFeatures = 2` and `maxStrongNonFacialFeatures = 1` for `surfaceMaterial`, `pattern`, and `effect`.
- All non-`none` `eyes`, `mouthShape`, and `oralDetail` selections must satisfy the same catalog face-inside and face-visible thresholds.
- Only explicit modifier semantics may duplicate or relocate a face; mode names alone do not relax face rules.
- Generate each of the three replacement art assets exactly once. Objective import failures stop the task and are reported; they do not trigger another creative generation call.
- Generate exactly one final review batch. Do not reject, replace, reroll, or regenerate entries based on agent visual judgment.
- The final batch decision is `pending_user_review`; only the user makes the visual approval decision.
- Preserve unrelated worktree changes and use `apply_patch` for source/document edits.

- [ ] **Step 4: Implement the minimal second budget**

Use literal slot membership, not ID/name inference:

```ts
const NON_FACIAL_SLOT_SET = new Set<VisualSlotId>(NON_FACIAL_VISUAL_SLOT_IDS)

export function strongNonFacialFeatureCountForSelections(
  selections: Partial<Record<VisualSlotId, { partId: string }>>,
  catalog: Catalog,
): number {
  return NON_FACIAL_VISUAL_SLOT_IDS.reduce((count, slotId) => {
    const partId = selections[slotId]?.partId
    const part = catalog.parts.find(item => item.slotId === slotId && item.id === partId)
    return count + (part?.composition?.visualIntensity === 'strong' && !part.composition.isNone ? 1 : 0)
  }, 0)
}
```
