# QMonster v0.6 AnatomyBundle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace v0.6 runtime head/body/tail bridging with a complete, deterministic feline AnatomyBundle pipeline while retaining local face, coat, pattern, and single-anchor mutation variation.

**Architecture:** A v0.6 spec will name one `anatomyBundleId`; the catalog resolves it to one complete structural asset and explicit local safe regions. Generator-core derives all structural visual slots from that bundle, and the renderer draws the bundle once before clipping local layers. The legacy attachment/interface/bridge renderer remains unchanged for v0.1–v0.5.

**Tech Stack:** TypeScript, Zod, Vitest, React, Canvas 2D, Playwright Chromium, existing asset catalog provenance/validation scripts.

**Spec:** `docs/superpowers/specs/2026-09-04-qmonster-v0.6-anatomy-bundle-design.md`

## Global Constraints

- Rewrite unreleased catalog `0.6.0` in place; do not introduce `0.7.0`.
- Preserve all v0.1–v0.5 schemas, catalogs, assets, seeds, imports and render paths unchanged.
- v0.6 supports only `archetypeId: 'feline'` and `rigId: 'feline-sit'`.
- v0.6 must not call `solveConnector`, transition bridges, bridge mesh, contour masks, or connector coverage policy.
- A v0.6 structural render is exactly one complete AnatomyBundle alpha silhouette; it includes head, ears, head-neck, body, four paws, tail root and one conventional cat tail.
- The first v0.6 catalog contains exactly eight complete feline-sit bundles.
- Keep the 14 visual-slot protocol, but derive `bodyFrame`, `headShape`, `arms`, `legs`, `tail`, and `extraAppendage` from the selected bundle. No individual structural selection, lock, or reroll is valid in v0.6.
- Face traits render only inside `faceSafeZone`; surface, pattern and color render only inside `surfaceClipMask`; one mutation/aberration renders only in its declared anchor region.
- Keep mutation and aberration mutually exclusive; permit no more than one local special feature.
- Preserve all user/unrelated worktree changes. Never run `git reset`, `git checkout --`, or broad `git add .`; stage paths task-by-task.
- Do not modify the 22 previously approved component source PNGs. New bundle sources are separate complete-animal source images with their own hashes and provenance.

## File Structure

| Unit | Responsibility |
| --- | --- |
| `packages/generator-core/src/contracts.ts` | Defines `AnatomyBundleDefinition`, bundle-derived composition metadata and `MonsterSpec.anatomyBundleId`. |
| `packages/generator-core/src/schema.ts` / `catalog-schema.ts` | Parses the v0.6 bundle contract while keeping legacy inputs valid. |
| `packages/generator-core/src/anatomy-bundle.ts` | Resolves bundle IDs, derives structural slots and validates bundle/spec compatibility. |
| `packages/generator-core/src/generate.ts` / `reroll.ts` | Chooses or rerolls whole bundles and keeps local rerolls structurally stable. |
| `scripts/prepare-v06-anatomy-bundles.ts` | Derives alpha, clip masks, face zones and anchor masks from full-animal sources. |
| `scripts/assemble-v06-catalog.ts` | Emits v0.6 catalog, runtime derivatives, source index and evidence with no bridge references. |
| `packages/renderer-canvas/src/anatomy-bundle.ts` | Produces the one-node v0.6 structural render plan and validates local drawing regions. |
| `packages/renderer-canvas/src/render.ts` | Routes v0.6 through the bundle renderer; leaves legacy connector rendering untouched. |
| `apps/creator-web/src/components/AnatomyBundlePanel.tsx` | Presents one “外形基因” selection and whole-appearance reroll. |
| `packages/incubator-adapter/src/*.ts` | Persists and restores `anatomyBundleId`, archetype and version tuple. |

The contract, asset, generator, renderer, UI/adapter, and acceptance tasks depend on each other in that order. They are not independent subprojects.
