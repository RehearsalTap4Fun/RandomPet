# QMonster v0.9 无眼窝母版与 PoseTemplate 几何合同设计

日期：2026-09-08

状态：设计已在会话中确认，待用户最终审阅本文档

## 1. 目标

发布 `catalog 0.9.0 + feline-sit-v2`，从生产设计上消除五官、装饰和具名特效相对母版偏移的问题。新版本采用无预烘焙眼窝的完整猫母版、机器可读的 `PoseTemplate`、局部 trait 源素材和统一编译器流程；`0.8.0 / feline-sit-v1` 保持只读，不再覆盖。

本方案继续借鉴 CryptoKitties 的产品结构原则：稳定的物种与姿势先于可变 trait，随机性发生在受控表型中。不推断或复制其未公开渲染实现，也不复用其美术、品牌或素材。

## 2. 已确认决策

1. `feline-sit-v2` 的头部母版不包含眼窝、眼白、虹膜、瞳孔或高光，只包含连续脸部毛发、鼻子、口鼻体块和头部轮廓。
2. `eyes` 是一个成对选择的完整 trait，一次提供左右眼的眼睑/眼窝阴影、眼球底色、虹膜、瞳孔和高光；左右眼不能分别随机成两个无关 trait。
3. 所有位置敏感槽位统一使用 `PoseTemplate`：`eyes`、`mouthShape`、`oralDetail`、`headAppendage`、`extraAppendage` 以及有明确身体语义的 `effect`。
4. trait 源素材使用局部坐标，不得在生成脚本内出现 `feline-sit-v2` 的 2048 画布绝对坐标。
5. 发布编译器是局部素材到 2048×2048 固定画布运行时图层的唯一坐标转换入口；正式 renderer 继续只执行单位矩阵全画布合成。
6. 先审核一张母版 landmark 覆盖图，再允许批量编译部件。自动化不通过主观筛选反复生成样本。
7. 新方案发布为 `catalog 0.9.0 + feline-sit-v2`。旧 `0.8.0 / feline-sit-v1` 只读保留，旧 spec 仍可复现。
8. 每个部位的普通、稀有、传说类型数量保持 `8:4:1`，各槽位均为 13 个 trait；比例影响类型池规模，不在运行时重新解释为抽取概率。

## 3. 当前失败的根因

### 3.1 实测偏差

当前 `feline-sit-v1` 母版眼窝暗部轮廓约为：

| 特征 | 母版实测中心 | v0.8 写死中心 | 中心偏差 |
|---|---:|---:|---:|
| 左眼 | `(789, 591)` | `(804, 630)` | 向右约 15px，向下约 39px |
| 右眼 | `(1187, 587)` | `(1244, 630)` | 向右约 57px，向下约 43px |

旧遮罩半径为 `126×132`，而母版眼窝可见暗部约为左 `103×83`、右 `108×82`。因此问题同时包含位置、尺寸和左右不对称三类误差。

### 3.2 为什么旧门禁错误放行

`v08-canonical-geometry.ts` 与眼睛生成代码共享了同一组硬编码坐标；`v08-visual-coherence.test.ts` 又检查遮罩中心是否落在由这组坐标推导的范围。测试只证明“生成代码与自己一致”，没有证明“结果与母版一致”。

正式 `species-rig-render` 以 2048×2048 单位矩阵绘制结构、trait 和 mask，没有对眼睛执行额外平移或缩放。偏移在素材生产阶段已经产生，renderer 只是忠实显示错误资产。

### 3.3 违反既有 v0.8 设计的地方

v0.8 设计要求区域必须沿母版实际结构手工描绘或从母版分区导出，并明确禁止用预设椭圆、宽泛多边形或画布中心猜测。实际实现却：

- 用椭圆重建 `eyesRegion`；
- 假设双眼关于 2048 画布中心对称，而母版脸部视觉中轴约在 x=988；
- 在各 trait 生成分支中直接写绝对坐标；
- 用“落在宽泛 owner mask 内”代替“命中具体语义位置”；
- 没有一份独立于生成代码的、经过视觉批准的 landmark 权威数据。

因此继续微调常量只会形成第三组猜测，不能消除复发机制。

## 4. 方案比较

### 4.1 方案 A：无眼窝母版＋PoseTemplate＋局部 trait 编译（采用）

母版不预烘焙可变五官。每个物种姿势拥有一份人工校准、绑定母版哈希的 `PoseTemplate`。trait 在局部画布制作，由编译器映射到左右眼、嘴、耳饰、项圈、爪、尾等具体 frame，再生成固定画布运行时资源。

该方案只有一个几何权威，能保留独立 trait、锁定、重掷和稀有度，同时适用于未来犬类与兔类。

### 4.2 方案 B：无眼窝母版＋人工对齐全画布 trait（不采用）

每张透明 PNG 仍由美术或脚本直接放在 2048 画布中。它减少了母版眼窝冲突，但每个 trait 都可以独立漂移，新增素材时仍需逐张人工校准，无法从数据层保证一致。

### 4.3 方案 C：每个眼型烘焙一张完整猫图（不采用）

它可以消除五官接缝，但会让眼睛、嘴、颜色和花纹组合数量指数增长，并破坏局部重掷、独立稀有度和孵化器可解释字段。

## 5. 几何权威

### 5.1 `PoseTemplate`

`PoseTemplate` 是物种姿势中所有位置敏感表型的唯一几何来源：

```ts
interface PoseTemplateV1 {
  schemaVersion: 'qmonster-pose-template-v1'
  id: 'feline-sit-v2'
  archetypeId: 'feline'
  poseId: 'feline-sit'
  canvas: { width: 2048; height: 2048 }
  sourceMasterSha256: string
  coordinatePolicy: 'local-source-compiled-to-fixed-canvas'
  face: {
    visualCenterline: Point2D
    nose: FeatureFrame
    eyes: PairedFeatureFrame
    mouth: FeatureFrame
    oral: FeatureFrame
  }
  attachments: {
    leftEar: FeatureFrame
    rightEar: FeatureFrame
    crown: FeatureFrame
    collar: FeatureFrame
    tailTip: FeatureFrame
  }
  effects: {
    leftFrontPaw: FeatureFrame
    rightFrontPaw: FeatureFrame
    leftEar: FeatureFrame
    rightEar: FeatureFrame
    tail: FeatureFrame
    floorBaseline: FeatureFrame
    breath: FeatureFrame
  }
  regions: Record<V09RegionId, ResourceRef>
  approval: {
    overlayPath: string
    overlaySha256: string
    approvedMasterSha256: string
  }
}

interface Point2D { x: number; y: number }

interface FeatureFrame {
  center: Point2D
  axisX: Point2D
  axisY: Point2D
  safePolygon: Point2D[]
}

interface PairedFeatureFrame {
  left: FeatureFrame
  right: FeatureFrame
  pairSafePolygon: Point2D[]
}

type V09RegionId =
  | 'bodySurface'
  | 'headSurface'
  | 'faceSafeZone'
  | 'eyesSafeZone'
  | 'mouthRegion'
  | 'oralRegion'
  | 'tailSurface'
  | 'frontPawDetail'
  | 'hindPawDetail'
  | 'headAccessory'
  | 'mutationEar'
  | 'mutationCollar'
  | 'mutationTailTip'
  | 'effectField'
  | 'faceProtection'
```

`axisX`、`axisY` 同时表达局部尺寸、旋转与非对称性。左右眼各有独立 frame，不再通过画布中心镜像推算。`safePolygon` 是最大允许范围，不能由 trait 自己扩大。

`face.nose` 是只读、不参与渲染的参照 frame；鼻子仍属于母版，眼睛、嘴与口腔通过它校验相对关系，编译器不得额外绘制鼻子。

### 5.2 landmark 生产与审核

1. 从无眼窝母版的鼻子、口鼻体块、脸部中轴、耳根、爪部、尾部和地面接触线标注初始 landmark。
2. 生成一张固定格式覆盖图：母版、frame 轮廓、中心十字、语义名称和像素坐标同时可见。
3. 覆盖图由用户批准一次；批准记录绑定母版 SHA-256 和覆盖图 SHA-256。
4. 母版像素或 landmark 任一变化都会使批准失效，并禁止发布编译。

自动图像分析可提供初始建议和偏差报告，但不能在每次构建中重新推导坐标。否则算法或阈值变化会悄悄移动全部部件。

## 6. 无眼窝母版

`feline-sit-v2` 从当前完整猫结构重新制作，要求：

- 清除左右眼窝凹洞、眼白及眼部阴影边界；
- 用连续、方向一致的短绒覆盖原眼区；
- 保持头型、耳朵、鼻子、口鼻体块、颈部、躯干、四肢和尾巴不变；
- 2048×2048 RGBA，主体不裁剪、不移动、不缩放；
- 眼部修复区不得留下对某个眼型的固定轮廓。

母版必须先单独通过视觉审核，随后冻结哈希。眼睛 trait 不依赖母版中隐藏或半透明的预制眼窝。

## 7. 局部 trait 与编译

### 7.1 源素材合同

位置敏感 trait 不再直接提交全画布图层，而是提交局部 source bundle：

```ts
interface LocalTraitBundleV1 {
  schemaVersion: 'qmonster-local-trait-v1'
  traitId: string
  slotId: 'eyes' | 'mouthShape' | 'oralDetail' | 'headAppendage' | 'extraAppendage' | 'effect'
  speciesRigId: 'feline-sit-v2'
  sourceMasterSha256: string
  elements: Array<{
    target: V09FeatureTarget
    assetPath: string
    localCanvas: { width: number; height: number }
    localOrigin: Point2D
  }>
}

type V09FeatureTarget =
  | 'leftEye'
  | 'rightEye'
  | 'mouth'
  | 'oral'
  | 'leftEar'
  | 'rightEar'
  | 'crown'
  | 'collar'
  | 'tailTip'
  | 'leftFrontPawEffect'
  | 'rightFrontPawEffect'
  | 'leftEarEffect'
  | 'rightEarEffect'
  | 'tailEffect'
  | 'floorBaseline'
  | 'breath'
  | 'ambient'
```

局部 PNG/SVG 的坐标只相对于自己的 `localCanvas`。源文件、manifest 和生成代码不得包含 2048 母版坐标。

### 7.2 完整成对眼睛

一个 `eyes` trait bundle 必须同时声明 `leftEye` 与 `rightEye` 两个元素。每个元素包含眼睑/眼窝阴影、眼球底色、虹膜、瞳孔和高光。两者共享一个 trait ID、稀有度和重掷生命周期，但分别进入左右非对称 frame。眼睛类型池固定为普通 8、稀有 4、传说 1。

普通差异只改变虹膜色、瞳孔、眼睑开合和高光；稀有与传说可改变内部图案和发光，但外轮廓仍必须落在对应 `safePolygon` 内。

### 7.3 其他位置敏感槽位

- `mouthShape` 以鼻子和嘴部 frame 为基准；不能以画布中心为基准。
- `oralDetail` 直接以 PoseTemplate 的 `face.oral` frame 为唯一基准，并受 `oralRegion` 限制；mouth trait 不得另行定义或移动 oral frame。
- `headAppendage` 只能选择左耳、右耳或 crown target；装饰必须与对应结构区相交。
- `extraAppendage` 只能选择 collar 或 tailTip target；普通模式不产生脱离身体的独立轮廓。
- 命名 effect 必须声明 target。`paw-glow`、`ear-glint`、`tail-spark`、`floor-spark` 和 `breath-mist` 分别编译到对应 frame；只有 `ambient` 类效果允许在 effect field 内分布。

### 7.4 编译结果

`compileLocalTrait(bundle, poseTemplate)` 输出一张 2048×2048 RGBA PNG：

1. 校验 bundle、template 和 master 哈希一致；
2. 根据 target 取得唯一 `FeatureFrame`；
3. 用 frame 的两个轴计算局部到母版的仿射矩阵；
4. 将局部元素绘制到透明 2048 画布；
5. 与 target `safePolygon` 和 owner mask 求交；
6. 写入编译 provenance、输入哈希、矩阵和输出哈希；
7. 编译后的运行时图层固定使用单位矩阵，不允许 renderer 再次定位。

## 8. 数据流与唯一入口

```text
无眼窝母版 + 人工批准 PoseTemplate
              ↓
       LocalTraitBundle
              ↓ compileLocalTrait（唯一坐标转换）
       2048×2048 runtime layer
              ↓ assemble catalog 0.9.0
       SpeciesRig feline-sit-v2
              ↓ species-rig-render（单位矩阵）
 creator / report / CLI / incubator
```

网页、目录报告、批量脚本和孵化器不得读取局部源素材，也不得执行 landmark 映射。它们只消费已经编译并经哈希验证的 catalog/runtime layer。

## 9. 发布门禁

### 9.1 独立权威门禁

- `PoseTemplate.sourceMasterSha256` 必须等于无眼窝母版哈希。
- landmark 覆盖图批准哈希必须存在且与当前 template/master 匹配。
- 生成脚本扫描不得发现 `feline-sit-v2` 的母版绝对坐标字面量；只有 PoseTemplate 数据可包含这些数值。
- 运行时 catalog 不得接受未经过 `compileLocalTrait` provenance 的位置敏感部件。

### 9.2 几何门禁

- 每个编译元素的可见 alpha 质心与目标 frame 中心的误差不超过 frame 短轴的 5%。
- 每个元素至少 99.5% 可见 alpha 位于 target `safePolygon` 内，100% 位于 owner mask 内。
- 成对眼睛必须恰好产生两个主要连通组件；每个组件分别命中 left/right frame，不能跨越脸部中轴。
- 眼睛 pair 的整体包围盒必须位于 `pairSafePolygon` 内，并与 nose frame 保持模板声明的最小间距。
- 头饰和附属物必须与对应母版结构 alpha 相交至少 500 像素；非 `ambient` effect 必须与命名目标区域达到各自阈值。
- 编译矩阵必须完全由 template frame 与 local canvas 推导；catalog 和 renderer 不允许附加 transform。

### 9.3 最终合成门禁

测试必须从最终 2048 合成图中隔离位置敏感图层，重新测量其质心、包围盒、owner overlap 和目标 overlap。测试比较的是最终输出与已批准 PoseTemplate，而不是比较 mask 与生成代码中的同一常量。

至少覆盖：

- 所有 13 个 `eyes` trait；
- 所有 mouth/oral/headAppendage/extraAppendage trait；
- 每个具名 effect；
- 同一 trait 经 creator、report、CLI 三个入口的像素哈希一致；
- 10 个固定 seed 一次性用户审核批次，无重抽、无替换 seed。

## 10. 失败策略

以下任一情况立即失败关闭，不发布、不自动移动素材、不改用备用坐标：

- 母版或 template 与批准哈希不一致；
- trait 缺少 target、局部 origin 或编译 provenance；
- 元素超出 safe polygon/owner mask；
- 眼睛连通组件数量、左右归属或中心误差不合格；
- renderer/catalog 出现第二次定位或非单位变换；
- 旧版资产被写入 `0.9.0` 可达池；
- 用户尚未批准无眼窝母版或 landmark 覆盖图。

诊断必须包含 catalog version、species rig、trait ID、target、期望 frame、实测中心、误差和阈值。

## 11. 版本与迁移

- `0.8.0 / feline-sit-v1` 文件、catalog、source index 和渲染注册保持只读。
- 新建 `0.9.0 / feline-sit-v2`，使用新的 master、template、masks、trait source index 和 evidence manifest。
- 旧 genome/spec 继续按其 `catalogVersion` 与 `speciesRigId` 渲染。
- 新生成默认切换到 `0.9.0`；孵化器必须原样保存 `catalogVersion`、`speciesRigId` 和 `poseTemplateId`。
- 迁移只复用 trait 的语义、ID 后缀、稀有度和配色意图；所有位置敏感运行时图层重新编译，不复制 v0.8 全画布像素。

## 12. 未来狗与兔子

`canine` 和 `lagomorph` 分别提供独立的无眼窝母版与 PoseTemplate。它们复用 schema、局部 trait bundle 格式、编译器和门禁，但不复用猫的 landmark、safe polygon、mask 或编译输出。

跨物种复用只能发生在不携带几何的数据层，例如颜色名称、瞳孔语义或稀有度标签。实际局部素材必须明确声明兼容的 species rig，并针对该 template 编译。

## 13. 非目标

- 不修改 v0.1–v0.8 的历史视觉结果。
- 不恢复运行时 connector、trim、自动居中或自由 transform。
- 不增加繁育、显隐性基因或市场逻辑。
- 不通过生成更多随机样本代替 landmark 审核。
- 不在本阶段重做全部美术风格；本方案只确保几何归属与组合稳定。

## 14. 完成定义

只有以下条件全部成立，偏移问题才算解决：

1. 用户批准无眼窝 `feline-sit-v2` 母版和带坐标的 PoseTemplate 覆盖图。
2. 所有位置敏感 trait 都来自局部 source bundle，生产代码中不存在母版绝对坐标。
3. 全部 trait 和最终合成门禁以批准的 PoseTemplate 为独立期望值并通过。
4. creator、catalog report、CLI 和孵化器消费同一 `0.9.0` catalog 与同一正式 renderer。
5. 旧 `0.8.0` spec 可继续只读复现，且发布过程没有覆盖旧资产。
6. 10 个固定 seed 只生成一次并交由用户审核；系统不进行主观重抽。
