# QMonster v0.6 AnatomyBundle 设计

日期：2026-09-04；状态：已确认，待实施规划

## 背景

v0.6 的现有方向虽然限制为猫原型，却仍将猫头、躯干与尾巴作为独立的结构图片，在运行时通过 connector、轮廓遮罩与桥接网格拼接。该做法可以检测几何问题，但不能保证共同骨架、绒毛方向、光照和负形连续；因此会出现“位置正确却不像一个生物”的结果。

本设计借鉴 CryptoKitties 的结构策略，而不复用其美术、名称、素材或繁育规则：先选择一只完整、可辨认的动物姿势，再只在有限的安全区内改变表型。

## 目标

1. v0.6 每次生成首先得到一个完整连续的猫轮廓，不再由运行时头颈或尾根桥接决定结构成立与否。
2. 保留随机性，但将其限制为完整外形、脸部、毛色、花纹与一个小异化锚点五个层级。
3. 保留现有 14 个视觉槽位的可读性及孵化器兼容字段，同时禁止 v0.6 独立重掷结构零件。
4. 为狗、兔子等未来原型提供可复用的 bundle 契约，但绝不允许跨物种拼接。

## 非目标

- 不修改或迁移 v0.5 及以前的 spec、目录、存档或渲染行为。
- 不实现繁育、跨物种杂交、自动视觉复审或重生成。
- 不在 v0.6 运行时重建头颈、尾根或四肢桥接。
- 不引入统一 3D 网格、骨骼绑定或新的实时 3D 渲染管线。

## 核心模型

### AnatomyBundle

`AnatomyBundle` 是一个已经完成的同物种、同姿势、同一美术光照关系的结构资产。它包含猫头、双耳、头颈、躯干、四爪、尾根及一条合法猫尾；所有这些区域共同构成一个连续 alpha 轮廓。

每个 bundle 至少声明：

```ts
interface AnatomyBundle {
  id: string
  archetypeId: 'feline' | 'canine' | 'lagomorph'
  rigId: string
  poseId: string
  structuralAsset: ResourceRef
  structureAlphaMask: ResourceRef
  surfaceClipMask: ResourceRef
  faceSafeZone: Rect
  featureSockets: {
    eyes: Point
    mouth: Point
    oralDetail?: Point
    headAppendage?: Point
  }
  mutationAnchors: Record<string, AnchorRegion>
  derivedSlots: {
    bodyFrame: string
    headShape: string
    tail: string
    arms: string
    legs: string
    extraAppendage: string
  }
  allowedTraitPools: TraitPoolRules
  silhouetteTags: string[]
}
```

`structuralAsset` 是唯一的 v0.6 结构绘制来源。`structureAlphaMask` 用于结构连续性与画布边界校验；`surfaceClipMask` 用于毛色、材质和花纹裁切。所有 `ResourceRef` 都使用现有的路径、哈希和 provenance 机制。

### MonsterSpec

v0.6 `MonsterSpec` 新增必填 `anatomyBundleId`。`bodyFrame`、`headShape`、`tail`、`arms`、`legs` 与 `extraAppendage` 继续出现在 `visualSlots` 内，但仅能由 bundle 的 `derivedSlots` 派生，不能独立抽取、独立锁定/重掷或拥有 v0.6 render node。

一个合法 v0.6 spec 必须满足：

- `anatomyBundleId` 属于指定 `archetypeId` 与 `rigId`；
- 全部六个结构槽位与该 bundle 的 `derivedSlots` 完全一致；
- 每个面部或表面 trait 属于 bundle 声明的允许池；
- mutation 与 aberration 仍互斥，且最多一个；
- 任何不一致都失败关闭，不回退至 connector 拼接或旧 catalog。

首发继续使用 `archetypeId: 'feline'` 与 `rigId: 'feline-sit'`。v0.6 尚未正式对外接入，因此在该版本内替换当前 interface/bridge 模型，不另建 v0.7。

## 生成规则

生成顺序固定如下：

1. 校验版本和 `archetypeId`，固定为 `feline-sit`。
2. 抽取一个合法 `AnatomyBundle`，并将其六个结构槽位写入派生值。
3. 在 bundle 允许池中抽取毛色、材质与花纹。
4. 在该 bundle 的 `faceSafeZone` 和 feature sockets 中抽取眼睛、嘴与口腔细节。
5. 正常模式不抽特殊特征；mutation 或 aberration 模式最多抽一个 bundle 允许的局部锚点特征。
6. 校验 spec、资源哈希、结构 alpha、裁切区域与画布边界。

重掷规则：

- `reroll appearance` 更换完整 bundle，并重新抽取所有依赖它的局部 trait；
- 面部、毛色、花纹及小异化重掷不改变 bundle；
- 不存在 v0.6 独立的“重掷头”“重掷躯干”“重掷尾巴”操作；
- 锁定任一结构槽位等价于锁定整个 `anatomyBundleId`。

## 渲染顺序

```text
AnatomyBundle structural asset
  → surface material（surfaceClipMask）
  → pattern / color（surfaceClipMask）
  → face traits（faceSafeZone）
  → one local mutation / aberration（declared anchor）
```

v0.6 bundle renderer 不调用 `solveConnector`、transition bridge、connector contour 或 connector coverage policy。旧版本仍走旧接口渲染路径。结构层只有一个连续主体；尾巴已包含在 bundle 内，因此不存在额外尾根接缝。

## 美术与资产规则

- 每个猫 bundle 必须由统一构图生成或由美术在同一画面完成，采用正面居中坐姿、可辨认的猫头、双耳、四爪与单条长条状猫尾。
- 首批准备 6–12 个经过人工选择的猫 bundle；不同 bundle 可以改变体态比例、毛感、尾巴弯曲与局部猫科特征，但都必须保持同一 `feline-sit` 阅读方式。
- 眼睛、口型、图案与材质只提供局部资源或参数化颜色，不提供覆盖完整身体的独立结构贴片。
- 特殊特征只允许耳缘、背部、尾端或小面积体表锚点；不可增加头、肢体、翅膀、浮空物或新的主轮廓。
- 每个 bundle 的结构图、结构 alpha、表面裁切遮罩、脸部区与锚点必须从同一源画面导出，并纳入 source index 与 evidence manifest。

## 渲染与校验

v0.6 的必需校验：

1. bundle structural alpha 是单一连通主体，包含头颈、躯干、四肢和尾巴；
2. 可见结构与 surface/pattern/color 输出均位于画布边界内；
3. surface/pattern/color 所有可见像素都位于 `surfaceClipMask`；
4. 眼睛、嘴和口腔细节都位于 `faceSafeZone`，且可见比例符合现有 face policy；
5. mutation/aberration 像素位于其显式 anchor 区；
6. 同 seed、同版本、同 bundle catalog 得到相同 spec 和像素输出；
7. bundle 或派生结构槽位缺失、哈希不匹配、越界或不兼容时失败关闭。

v0.6 删除 connector coverage、bridge gap、bridge mesh 与 connector frontier 等作为运行时验收条件。它们可保留在旧版本测试与兼容 renderer 中，但不得阻断 bundle renderer。

## 生成器与孵化器接入

生成器：

- 将结构区改名为“外形基因”，显示 bundle 的名称、姿势和稀有度；
- 删除独立结构槽位的 reroll 控件；
- 提供“重掷外形”入口，锁定时明确提示会锁定整个外形；
- 保持脸、毛色、花纹与小异化的局部重掷和锁定体验。

孵化器：

- 请求与存档写入 `anatomyBundleId`、`archetypeId`、schema/catalog/renderer 版本；
- 展示结构槽位时使用 bundle 派生的展示名；
- 旧版本继续按旧 slot/spec 只读展示，不自动迁移；
- 未知 bundle 或 archetype 显示显式版本协商错误，不按默认猫渲染。

## 扩展到狗与兔子

`canine`、`lagomorph` 未来分别创建独立的 pose kit 与 AnatomyBundle 家族。它们拥有独立的面部区、尾根构图、四肢关系、可用 trait 池和特殊锚点。可复用的只有 catalog schema、随机权重、裁切机制和失败关闭规则；绝不共享结构资产或将跨物种部件混拼。

## 迁移与兼容

- v0.1–v0.5 catalog、种子、存档和 renderer 不改动；
- 当前未正式接入的 v0.6 interface/bridge 目录内容由 AnatomyBundle catalog 替代；
- v0.6 导入只接受携带有效 `anatomyBundleId` 的 spec；不支持从旧 structure slot 猜测 bundle；
- source index、production validation、孵化器适配文档与 acceptance 资产按新的 bundle 路径同步更新。

## 验收清单

- 每个初始猫 bundle 可独立生成、渲染和导出；
- 任意 seed 输出恰好一个完整外形 bundle，无运行时 bridge；
- 结构 alpha 连通、画面未越界、面部和表面裁切均通过；
- 各局部重掷保持外形不变，外形重掷才改变 bundle；
- 旧 catalog 回归与导入浏览保持不变；
- 孵化器可以持久化、恢复和显示 v0.6 bundle spec；
- 未来 dog/rabbit fixture 可使用同一契约，不依赖猫的结构假设。
