# QMonster v0.6 猫原型与有限异化设计

日期：2026-09-03；状态：设计已确认，待实施规划

## 背景与目标

当前 v0.5 允许 `blob`、`biped`、`floating` 三种骨架以及十四个视觉槽位独立组合。即使每个组件满足 slot、rig、socket 和主题兼容性，仍可能得到“部件位置正确、整体却不像生物”的结果：躯干、头部和四肢不共享同一解剖轮廓，纹理与特效也可能成为浮在身体外的独立视觉对象。

v0.6 将生成策略改为“动物原型优先，特征后置”。首版只提供猫（`feline`）原型，采用正面居中坐姿的 Q 版比例：圆头、双耳、四爪、短躯干与从侧后方自然延展的单条猫尾。目标是先让任何输出都可被辨认为猫，再通过有限异化形成熟悉的陌生感。

以太猫只作为姿态与异化强度的设计参照，不复用其美术、角色、命名或素材。项目继续采用现有 3D 毛绒怪奇美术。

## 版本与兼容性

- 新规则发布为独立 catalog `v0.6.0`，建议配套 spec schema `0.2.0`。
- v0.5 及更早 catalog、资产、种子、已生成 spec 和孵化器存档不被改写或迁移；它们继续使用各自版本校验与只读渲染。
- v0.6 spec 必须写入 `archetypeId: "feline"`。请求、存档和孵化器接入以 `(schemaVersion, catalogVersion, rendererVersion, archetypeId)` 协商，不得在不匹配时猜测或降级。
- 首版若收到非 `feline` 的 v0.6 请求，应返回显式的“不受支持原型”诊断；不得回退为任意旧骨架。

## 原型契约

新增以数据表达的动物原型定义，而不是在生成器中硬编码“猫”。每个原型至少声明：

- `id`、显示名与基础姿势；
- 合法 rig 集合及唯一的默认 rig；
- 必备解剖标志与结构槽位；
- 允许的结构组件、表面组件和特殊特征锚点；
- 用于渲染与验收的轮廓要求。

v0.6 仅定义 `feline` 与一个 `feline-sit` rig。未来可添加 `canine`、`lagomorph` 等原型，但每种动物都要有自己的骨架、头部接口、四肢关系和尾根；不同原型禁止混用头、躯干、肢体或尾巴组件。可跨原型复用的仅是颜色、材质、花纹类别、概率框架和通用校验机制。

## 猫的不可变结构

`feline-sit` 是唯一可抽取的 v0.6 rig，构图固定为正面居中坐姿。一个合法输出必须含有：

1. 一个完整猫头及一对猫耳；
2. 一个连续的躯干；
3. 两只前爪与两只后爪；
4. 一条从侧后方 `tailRoot` 连续连接的猫尾；
5. 正面坐姿下稳定的脸部安全区。

为消除结构组件之间的自由叠加，`bodyFrame` 资产必须拥有躯干、四爪、颈部接收区和尾根接收区。它是完整连续的基础轮廓，而不是仅供手脚贴上的空躯干。

`headShape` 是“完整猫头 + 双耳”接口组件，只能连接到同一结构变体声明的颈部 connector。眼睛、口型、口腔细节与耳内细节均只能绘制于该头部的 face-safe zone，不能改变头、耳或口鼻的基础位置。

为维持外部 `MonsterSpec` 的槽位可读性，`arms`、`legs` 与 `extraAppendage` 在 v0.6 不再是独立的结构抽取来源：

- `arms` 与 `legs` 使用不可见的 canonical 集成占位 part，标记为 `isNone`，不含 render node；
- `extraAppendage` 仅允许同类的空占位 part；
- 所有实际四肢视觉均由 `bodyFrame` 表达。

尾巴始终为一条连续的猫尾。其可变维度是长度、自然弯曲和末端毛簇；不得无尾、分叉、鱼尾、扇面尾、簇状尾或独立漂浮尾。每个尾巴变体必须通过同一 `feline-sit.tailRoot` 的连接器、遮罩和桥接验证。

## 可变特征与异化上限

所有随机变化先受 `archetypeId` 过滤，再受 slot、rig、connector 与主题约束过滤。特征分为四层：

| 层级 | 内容 | 对轮廓的影响 |
| --- | --- | --- |
| 基础外观 | 毛长、毛色、主/辅/强调色 | 无 |
| 表面花纹 | 虎斑、斑点、渐变、晶点、局部高光 | 不得越过身体或头部遮罩 |
| 面部表现 | 眼形、瞳色、口型、腮部、耳内细节 | 仅限 face-safe zone |
| 特殊特征 | 耳缘、背部或尾端的单一小范围变化 | 仅限一个指定锚点 |

普通输出不含特殊特征；`mutation` 或 `aberration` 模式最多只能激活一个。两种模式都不得复制头脸、增加肢体、改变坐姿、创建翅膀、形成浮空部件，或用多个强特征叠加制造新的生物结构。允许的陌生感包括苔藓绒毛、晶点、发光斑、异色瞳、局部卷毛和小范围耳缘/背部/尾端装饰。

`surfaceMaterial`、`pattern` 与 `colorScheme` 必须携带对应猫头或猫躯干的遮罩/裁切信息。渲染后任何这些层的非透明像素都必须落在其归属的可见轮廓内；它们不能作为完整的前景贴片出现。

## 生成与重掷

v0.6 生成顺序为：

1. 校验请求的 `archetypeId` 与版本协商；
2. 固定 `feline-sit` rig，并选择兼容的完整猫躯干和专属头部接口；
3. 在猫脸安全区内抽取五官；
4. 抽取并裁切表面、花纹和配色；
5. 按模式决定是否抽取一个合法的特殊特征；
6. 对连接器、轮廓、遮罩、语义与版本进行失败关闭校验。

重掷面部、花纹、材质或特殊特征时，`archetypeId`、坐姿猫 rig、完整躯干和已选结构接口均不得改变。未来若开放“重掷物种”，它必须是显式高层操作，并重新选择完整 archetype；不得借由普通槽位重掷意外换成狗或兔。

## 孵化器接入

- 创建蛋和生成请求均传递 `archetypeId`；首版固定为 `feline`。
- 响应 spec 回传 `archetypeId`、catalog 与 renderer 版本，供孵化器持久化与预览。
- 孵化器只展示当前协商版本声明的特征名与稀有度；未知 archetype 或部分字段不能按默认猫处理。
- 既有 v0.5 接入保持可用，新旧版本并存；不自动升级历史角色。

## 验收与回归

1. 同 seed、同版本、同主题、同 `archetypeId` 必须生成完全一致的 spec 与像素结果。
2. 每个 v0.6 spec 都必须只使用 `feline-sit` 和 `feline` 兼容组件，且轮廓语义含一头、双耳、四爪和单尾。
3. 猫头—颈部与尾巴—tailRoot 必须通过现有 connector 覆盖率、外露比例、结构连通率与层级校验。
4. 躯干与四肢的 alpha 区域必须形成单一连续主体；纹理、材质与配色不得在遮罩外留下可见像素。
5. 每份 spec 的特殊特征数量不得超过一项，并且该项必须命中其声明锚点。
6. `arms`、`legs`、`extraAppendage` 不得在 v0.6 输出新的独立 render node。
7. v0.5 的固定种子、旧 catalog 校验、渲染和孵化器只读预览必须保持通过。

## 非目标

- v0.6 首发不制作狗、兔或其他动物的素材；只建立可扩展 archetype 契约。
- 不修改或删除 v0.5 与更早版本的资产、用户批次或存档。
- 不引入繁育系统、跨物种杂交或自动视觉审核/重生成。
- 不复制以太猫的具体美术、素材、角色、名称或游戏规则。
