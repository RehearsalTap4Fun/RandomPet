# QMonster v0.8 统一物种骨架与受控表型设计

日期：2026-09-08
状态：已完成会话内设计确认，待用户审阅本文档

## 1. 背景与根因

QMonster 已先后尝试画布锚点、挂点树、结构连接器、软组织桥、视觉层级、单头长尾、猫原型和 AnatomyBundle。它们分别解决了定位、诊断、注意力和物种识别中的一部分问题，但最近的 v0.7 随机组合仍出现头身、四肢、尾巴和表面纹理衔接异常。

根因不是某个坐标错误，而是系统不存在一份被素材生产、目录校验、正式渲染器、测试组合器和网页共同执行的几何合同：

- 独立生成的透明 PNG 虽然尺寸相同，内部轮廓、留白、光照和连接切口并不相同；
- `trim()`、自动居中和硬编码坐标会破坏透明留白所代表的画布位置；
- 躯干素材可能已包含四肢，独立手脚素材再次叠加后产生重复结构；
- 锚点配置存在于素材目录，但 v0.7 测试组合器和当前网页没有实际读取；
- v0.7 为十四个槽位恢复独立结构替换，违背了 v0.6 AnatomyBundle 的完整结构原则。

因此，v0.8 不再继续调整散件坐标，而是建立唯一的物种骨架合同，并将可随机变化的内容限制为该骨架上的受控表型。

## 2. 已确认的产品决策

1. 现有 v0.7 结构素材不进入 v0.8 正式目录；它们被隔离保留，不删除。
2. 旧颜色、纹理和特效仅在通过 v0.8 区域门禁后迁移。
3. 猫的基础头部轮廓、头颈、躯干、四肢、尾根和完整猫尾由同一个 AnatomyBundle 提供，运行时不再拼接这些结构。
4. 借鉴 CryptoKitties 的结构策略：先保证固定、熟悉、可辨认的猫，再在固定特征类别中进行有限异化；不复用其美术、品牌、名称、角色或繁育规则。
5. 首次交付只实现 `feline / feline-sit`。狗和兔子以后分别建立独立母版、骨架合同和素材池，禁止跨物种混用结构素材。
6. 部件级普通、稀有、传说继续使用 `N:R:L = 8:4:1`；整只外形的 collection rarity 保持独立配置，二者不能共用权重常量。
7. 自动化只负责客观几何与资源合同，不在生产过程中反复进行主观审核或自动重生成；最后的视觉判断由用户完成。

## 3. 目标与非目标

### 3.1 目标

- 任意通过 v0.8 目录门禁的合法组合都不能产生头身断裂、重复四肢、尾巴悬空或纹理漂浮。
- 素材生产、目录、生成器、正式渲染器、网页、测试和报告使用同一份 `SpeciesRigContract`。
- 保留十四个视觉基因槽位、固定 seed、锁定、局部重掷、稀有度报告和孵化器字段兼容性。
- 将结构随机性从“任意身体散件互换”改为“完整外形选择＋受控区域表型”。
- 为未来犬类和兔类提供可复制的数据合同，而不是复用猫的坐标或图片。

### 3.2 非目标

- 不实现繁育、遗传显隐性、市场经济或 CryptoKitties 的游戏规则。
- 不允许跨物种结构混合、双头、分叉尾、鱼尾、扇面尾或新增主轮廓的大型漂浮物。
- 不为 v0.8 保留旧 connector/bridge 作为静默回退。
- 不删除或重写 v0.1–v0.7 的历史目录、存档和只读渲染能力。
- 不要求自动化替代用户的美术审美判断。

## 4. 方案比较与选择

### 4.1 方案 A：完整物种骨架＋受控表型（采用）

每个 AnatomyBundle 是一只结构完整的猫。颜色、材质、花纹、五官和小范围异化只能在骨架声明的区域内表达。十四个基因槽位仍可独立抽取稀有度和 trait ID，但不再都拥有独立结构拓扑。

优点是结构连续性由素材本身保证，随机组合不会重新制造接缝；未来物种也可用相同 schema 建立自己的合同。代价是头、四肢和尾巴的大幅形变必须作为新的完整 AnatomyBundle 制作，不能随意与其他身体交叉组合。

### 4.2 方案 B：全模块连接器继续演进（不采用）

为每个头、躯干、四肢和尾巴维护 plug、receiver、轮廓、材质采样和桥接图。它能保留最高结构组合数，但需要近似骨骼绑定的制作精度，且 2D 毛绒图的绒毛方向、光照和负形仍难通过运行时桥接统一。历史 v0.3–v0.6 已证明该路线能检测问题，却不能稳定消除“拼出来”的观感。

### 4.3 方案 C：每只成品整图预烘焙（不采用）

每一种组合直接生成整只猫，视觉最稳定，但失去独立基因、锁定、局部重掷和可解释稀有度，素材数量也随组合指数增长。

## 5. 唯一运行架构

```text
MonsterGenome
  ↓ 确定性选择
v0.8 Catalog
  ↓ 只引用已发布的合同与资源
SpeciesRigContract + AnatomyBundle
  ↓ 固定画布、固定区域、固定层级
renderer-canvas 唯一正式渲染入口
  ├─ creator-web 实时预览与导出
  ├─ catalog-report 缩略图
  ├─ CLI 固定种子测试
  └─ incubator-adapter 结果交付
```

以下行为在 v0.8 中禁止：

- 在网页、报告或脚本中重新实现一套部件坐标；
- 对素材执行 `trim()`、按可见边界居中或按内容自动缩放；
- 在缺少 v0.8 合同时退回 v0.7 锚点或 v0.3 connector；
- 从文件名推断槽位、锚点、物种或遮挡关系；
- 让测试组合器绕过正式 catalog 和 renderer。

## 6. `SpeciesRigContract`

v0.8 增加版本化物种骨架合同。首版接口和十五个区域名称固定如下；后续扩展通过新 catalog 版本演进，不在运行时接受自由命名的区域：

```ts
interface SpeciesRigContract {
  schemaVersion: 'qmonster-species-rig-v1'
  id: string
  rigVersion: string
  archetypeId: 'feline' | 'canine' | 'lagomorph'
  poseId: string
  canvas: { width: 2048; height: 2048 }
  coordinatePolicy: 'fixed-canvas-no-trim'
  regions: {
    bodySurface: ResourceRef
    headSurface: ResourceRef
    faceSafeZone: ResourceRef
    eyesRegion: ResourceRef
    mouthRegion: ResourceRef
    oralRegion: ResourceRef
    tailSurface: ResourceRef
    frontPawDetail: ResourceRef
    hindPawDetail: ResourceRef
    headAccessory: ResourceRef
    mutationEar: ResourceRef
    mutationBack: ResourceRef
    mutationTailTip: ResourceRef
    effectField: ResourceRef
    faceProtection: ResourceRef
  }
  layerOrder: VisualSlotId[]
  allowedSlotExpressions: Record<VisualSlotId, V08ExpressionKind>
  sourceMasterSha256: string
}

type V08ExpressionKind =
  | 'body-clipped'
  | 'head-clipped'
  | 'face-clipped'
  | 'anchor-clipped'
  | 'protected-effect'
```

`sourceMasterSha256` 将合同绑定到产生基础结构和全部区域蒙版的同一母版。合同、bundle 或 trait 的版本/哈希不一致时必须失败关闭。

`feline-sit-v1` 的 trait 图层顺序固定为：`colorScheme → surfaceMaterial → pattern → bodyFrame → tail → arms → legs → headShape → eyes → mouthShape → oralDetail → headAppendage → extraAppendage → effect`。完整 AnatomyBundle 结构始终先于该数组绘制，catalog 不得自行重排。

## 7. 完整结构与十四个槽位

### 7.1 几何权威

`AnatomyBundle.structural` 是唯一结构绘制来源，必须在一张图中包含：

- 一个完整猫头和双耳；
- 连续头颈与躯干；
- 与躯干自然连接的四肢和四爪；
- 从侧后方延展、根部被身体自然遮挡的一条猫尾；
- 一致的材质方向、光照和透视。

不同的体型、头身比例、四肢姿态或尾巴曲线只能通过另一个完整 AnatomyBundle 提供。运行时不得从多个 bundle 交叉抽取结构区域。

### 7.2 槽位语义

十四个槽位继续存在于 genome、spec、报告和孵化器输出中，但 v0.8 将“基因分类”与“独立结构图片”分离：

| 槽位 | v0.8 表达方式 | 不再允许 |
|---|---|---|
| `bodyFrame` | 完整 bundle 的体型表型或 bundle 派生标识 | 覆盖另一具躯干 |
| `headShape` | 头部区域内的耳毛、额毛、面颊轮廓细节 | 替换完整头颈 |
| `arms` | `frontPawDetail` 内的前爪纹样、爪尖、短毛簇等局部细节 | 叠加另一对手臂或进入后爪区域 |
| `legs` | `hindPawDetail` 内的后爪纹样、爪尖、短毛簇等局部细节 | 叠加另一对腿或进入前爪区域 |
| `tail` | 完整 bundle 派生的尾形标识及尾部内部细节 | 替换尾根或叠加鱼尾 |
| `extraAppendage` | 单一白名单 mutation anchor 内的小型特征 | 新头、成对翅膀或第二主轮廓 |
| `eyes` | `eyesRegion` 内的眼睛 | 越出眼区或形成第二张脸 |
| `mouthShape` | `mouthRegion` 内的嘴部 | 覆盖躯干或进入眼区 |
| `oralDetail` | `oralRegion` 内的牙、舌等 | 独立漂浮口腔物体 |
| `headAppendage` | 头部白名单区域内的小型装饰 | 改写颈部接缝 |
| `surfaceMaterial` | `bodySurface` 内的材质响应 | 完整不透明物体层 |
| `pattern` | `bodySurface`/`headSurface` 内的纹样 | 身体外可见像素 |
| `colorScheme` | 结构 alpha 内的参数化调色或颜色蒙版 | 覆盖轮廓的彩色整图 |
| `effect` | 遵守脸部保护区和边界预算的前/后景效果 | 未声明遮挡关系的贴片 |

每个槽位仍要求提供 `8 N / 4 R / 1 L` 个可达 trait。对于 `bodyFrame`、`headShape`、`arms`、`legs` 和 `tail`，这些 trait 必须在各自 owner mask 内产生可辨识的局部表型，允许多个 trait 共享同一份基础结构像素，但不能额外绘制躯干、头颈、肢体或尾根。稀有度提高视觉特征强度，不获得突破区域和骨架规则的权限。结构性稀有外形属于 collection-level AnatomyBundle，而不是局部结构散件。

## 8. 素材生产合同

### 8.1 母版优先

先制作并锁定 `feline-sit` 的 2048×2048 猫母版，再从同一母版导出结构图、结构 alpha、身体表面、头部表面、脸部安全区、独立眼区、嘴区、口腔区、尾部区域、独立前后爪区域、头饰区、mutation anchors、effect field 和脸部保护蒙版。

上述区域不得用预设矩形、椭圆或宽泛多边形猜测。母版通过后，所有身体、头部、脸部、五官、尾巴和爪部蒙版必须沿母版实际 alpha 手工描绘或从母版结构分区导出；前后爪蒙版互不相交，尾部蒙版只包含真实可见尾部。头饰和 mutation anchors 的最终蒙版必须扣除脸部保护区，effect 在渲染时再扣除脸部保护区。

任何新 trait 都必须使用该母版作为参考，并限制在合同允许的 mask 内进行编辑。不得从空白画布独立生成头、身体、四肢或尾巴。

### 8.2 文件规则

- 所有生产图均为 2048×2048 RGBA PNG；透明留白是坐标合同的一部分。
- 变换固定为单位矩阵：不平移、不缩放、不旋转、不镜像。
- 去背景流程只改变背景 alpha，不得裁边、重排或重新居中主体。
- trait 资源必须记录 `speciesRigId`、`rigVersion`、`sourceMasterSha256`、`regionId`、文件哈希和生成 provenance。
- AI 生成只可用于母版参考编辑或蒙版内变化；蒙版外差异像素必须为零。
- 素材进入目录前只执行一次生产；失败时记录失败原因并退出，不自动循环生成替代品。

### 8.3 旧素材迁移

- v0.7 的 `bodyFrame`、完整 `headShape`、独立 `arms`、独立 `legs` 和独立 `tail` 结构图全部隔离，不迁移。
- `surfaceMaterial`、`pattern`、`colorScheme`、五官和 effect 逐项投影到 v0.8 固定画布，并通过区域差异门禁；不能证明来源与区域的素材不迁移。
- 隔离项保留 manifest、原文件和拒绝原因，便于审计，但不出现在 v0.8 可达池。

## 9. 生成与稀有度

生成顺序固定为：

1. 校验 schema/catalog/renderer 版本和 `archetypeId`。
2. 选择一个完整、合法的 `feline-sit` AnatomyBundle。
3. 写入由 bundle 派生的结构身份，不产生额外结构 render node。
4. 对十四个表型槽位使用彼此独立的确定性子随机流。
5. 每个槽位按 `PART_RARITY_WEIGHTS = { N: 8, R: 4, L: 1 }` 选择层级，再在该层级的 bundle 兼容候选中选择 trait。
6. 应用锁定和局部重掷；任何局部重掷不得改变 AnatomyBundle。
7. 完成区域、资源和版本校验后才返回可渲染 spec。

整只外形的 collection rarity 继续使用独立配置。修改 collection rarity 不得改变部件级 8:4:1，反之亦然。

## 10. 渲染与失败策略

固定层级为：

```text
AnatomyBundle structural
  → body material / color / pattern（body/head masks）
  → paw / tail / head local details（owner masks）
  → eyes → mouth → oral detail（face masks）
  → head appendage / one local mutation（anchor masks）
  → protected effect（扣除 faceProtection）
```

renderer 必须使用完整画布直接合成。局部 trait 先与 owner mask 做 `destination-in`，再进入主画布；颜色和材质不能以不透明整图覆盖结构。

以下情况产生 error 并禁止预览提交与正式导出：

- rig、bundle、trait 的版本或母版哈希不一致；
- v0.8 结构槽位产生独立 connector/render node；
- trait 缺少 region、mask、资源或哈希；
- 素材尺寸不是 2048×2048，或声明了非单位变换；
- 合成后纹理/材质/颜色在 owner mask 外存在可见像素；
- 五官越出 face safe zone，effect 侵入 face protection；
- v0.8 请求试图回退到旧 renderer。

错误必须携带 catalog 路径、part ID、rig ID 和失败指标。系统不得静默移动素材、换候选或使用占位图完成正式输出。

## 11. 网页、报告与孵化器

- `creator-web` 默认加载 v0.8 catalog，并通过版本注册表调用正式 renderer。
- catalog report 使用同一 renderer 生成缩略图，展示每槽位 `8/4/1` 数量、contract 状态、bundle 兼容性和不可用原因。
- 固定种子批量测试通过公开生成 API 创建 spec，不允许注入图片或坐标。
- 孵化器存储 `archetypeId`、`anatomyBundleId`、`speciesRigId`、rig/catalog/schema/renderer 版本和十四个 trait ID。
- v0.1–v0.7 继续按各自 catalog 只读加载；不把旧结构 slot 猜测成 v0.8 bundle。

## 12. 自动门禁与验收

### 12.1 目录门禁

- 每个 v0.8 bundle 引用一份有效 `SpeciesRigContract`，且所有资源哈希匹配。
- 每个槽位有且仅有 8 个 N、4 个 R、1 个 L 的可达、可渲染 trait。
- 所有 trait 的 archetype、rigVersion、master hash 和 region 均与 bundle 一致。
- v0.8 catalog 中不存在 connector bridge、自由 transform 或无 owner mask 的局部图片。

### 12.2 像素门禁

- `surfaceMaterial`、`pattern`、`colorScheme` 在 owner mask 外的可见像素数为 0。
- 眼、嘴和口腔细节的可见像素至少 99% 位于各自允许区内。
- effect 在 `faceProtection` 内的可见像素数为 0，除非其类别被显式定义为脸部 trait。
- AnatomyBundle 结构 alpha 的主体为单一连通区域；尾根与躯干存在结构重叠，不依赖运行时桥接。
- 最终可见边界完全位于 2048×2048 画布内。

### 12.3 行为与集成门禁

- 同 seed、catalog 和 rigVersion 产生相同 spec 与像素哈希。
- 局部重掷只改变目标表型及明确依赖，不改变完整结构。
- creator、report、CLI 和孵化器适配测试调用同一 renderer，固定 fixture 输出一致。
- 旧版 spec 仍由旧版 catalog/renderer 只读渲染；未知版本失败关闭。
- 对连续 13,000 个固定 seed 执行属性测试，证明生成结果全部通过目录和像素门禁；每个槽位的 N/R/L 实际频率分别落在 `61.54% / 30.77% / 7.69%` 的绝对 ±2 个百分点内。

### 12.4 用户视觉验收

机器门禁全部通过后，只生成一次固定 seed 的 10 张 v0.8 加权组合联系表，附 manifest、trait 列表和版本哈希，交由用户审核。系统不因代理的主观判断自动删除、替换或重复生成样本。

## 13. 分阶段交付

1. **冻结与证据保全**：登记旧目录、临时组合器和 v0.7 结构素材的状态与拒绝原因。
2. **合同与 schema**：实现 `SpeciesRigContract`、v0.8 catalog 约束和失败关闭诊断。
3. **猫母版垂直切片**：交付一个完整猫 bundle、全部 mask 和每类最小 trait fixture。
4. **唯一渲染链路**：让 renderer、网页、报告和 CLI 全部读取同一合同；移除 v0.8 的 trim/硬编码路径。
5. **素材迁移与重建**：迁移合格局部资源，重建不合格资源，完成每槽位 8/4/1 可达池。
6. **生成器与孵化器接入**：完成确定性选择、锁定、重掷、版本协商和导出字段。
7. **全门禁与一次视觉交付**：运行自动测试并生成固定 10 张联系表供用户审核。

后续阶段不得在前一阶段门禁失败时通过添加坐标特判继续推进。

## 14. 完成定义

只有以下条件全部满足，v0.8 才算解决衔接问题：

1. v0.8 只有一个正式组合入口，网页、报告、CLI 与孵化器均不能绕过。
2. 完整猫结构只来自 AnatomyBundle，不存在运行时头颈、四肢或尾根拼接。
3. 每个局部 trait 都绑定相同母版、固定画布和明确 owner mask。
4. 所有合法组合都通过目录、像素、确定性和跨入口一致性门禁。
5. 每槽位部件级稀有度保持 8/4/1，且不改变 collection rarity。
6. 用户完成一次固定 10 张联系表的最终视觉审核。
7. 犬类或兔类扩展只需新增独立物种合同与素材，不需要修改猫的几何规则。

## 15. 参考边界
