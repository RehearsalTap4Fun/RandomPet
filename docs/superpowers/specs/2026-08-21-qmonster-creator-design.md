# QMonster Creator 设计规格

- 日期：2026-08-21
- 状态：已完成对话评审，待书面规格复核
- 项目目录：`C:\Project\QMonsterCreator`
- 参考产品：怪奇生物孵化器设计文档 v0.1

## 1. 背景

QMonster Creator 是从“怪奇生物孵化器”中独立出来的幻想怪奇生物生成器。它既是可直接操作的浏览器工具，也是孵化器可复用的生成核心。生成器负责以固定类别的随机特征组合出视觉完整、规则自洽、可复现的生物，并输出标准配方与透明成品图。

参考美术方向为明亮、圆润、触感明确的 3D 卡通：夸张比例、大眼、巨口、不规则牙齿、柔和棚拍光和友善的怪奇感。全局风格保持一致，但“表皮材质”仍可生成绒毛、软胶、鳞片、凝胶等不同触感；这些材质必须共享相同的卡通比例、镜头和灯光语言。

## 2. 目标与非目标

### 2.1 目标

1. 提供独立网页工具，支持主题与种子控制、整只随机、槽位锁定、局部重抽和手动选择。
2. 用带种子的确定性规则生成完整配方；同一配方在相同目录版本下必须复现同一画面。
3. 内部使用 14 个细粒度视觉槽位，并映射为孵化器兼容的 8 个语义槽位。
4. 复用孵化器的主题偏向、稀有度、互斥、联动、变异与畸变思想。
5. 使用标准化的 AI 辅助素材管线生产 3D 卡通透明部件。
6. 导出 `MonsterSpec` JSON 和透明 PNG/WebP。
7. 在 v0.1 中验证 AI 部件能否稳定拼装，而不是一次完成全部内容资产。

### 2.2 非目标

- 后端、账号、云同步和多人协作。
- 自由拖拽、任意缩放旋转或图层编辑等完整图形编辑能力。
- 生物动画和实时 3D 渲染。
- 一次完成孵化器的 10 个主题、103 条特征、8 条变异和 6 条畸变。
- 在本项目 v0.1 中直接修改孵化器代码库。

## 3. 已确认的产品决策

| 决策 | 结论 |
| --- | --- |
| 产品形式 | 浏览器网页生成器 |
| 视觉表现 | 标准化透明 WebP/PNG 部件拼装，保留 SVG 作为遮罩和定位工具 |
| 美术方向 | 明亮、圆润、触感明确的友善 3D 怪奇卡通 |
| 结构兼容 | 14 个视觉槽位映射到孵化器 8 个语义槽位 |
| 项目关系 | 独立工具与孵化器共享同一个生成核心 |
| 操作能力 | 随机、锁定、局部重抽、手动选择；不做自由拖拽 |
| 导出 | `MonsterSpec` JSON、透明 PNG、透明 WebP |
| 素材生产 | AI 基于锁定母体局部改绘，之后人工筛选和机器校验 |
| v0.1 内容 | 深海、菌沼、幽影；约 50 组部件；普通和稀有为主 |

## 4. 总体架构

项目采用 TypeScript Monorepo。两个应用消费者只能依赖共享包，共享包不得反向依赖应用。

```text
creator-web ──commands──> generator-core ──> MonsterSpec ──> renderer-canvas ──> preview / PNG / WebP
                                │                    │
                                └──── asset-catalog ─┘

incubator ──> incubator-adapter ──> generator-core / renderer-canvas
```

建议目录：

```text
apps/
  creator-web/
packages/
  generator-core/
  renderer-canvas/
  asset-catalog/
  incubator-adapter/
docs/
```

### 4.1 `apps/creator-web`

React + Vite 网页应用。只负责用户命令、编辑会话、诊断展示、预览和导入导出，不自行实现随机规则或图像合成规则。

### 4.2 `packages/generator-core`

纯 TypeScript 包，不依赖 DOM、Canvas 或 React。负责：

- 带种子的 PRNG 与槽位子种子。
- 主题池、稀有度、互斥和联动权重。
- 锁定与局部重抽规则。
- 14 个视觉槽位到 8 个语义槽位的映射。
- `MonsterSpec` Schema、解析、校验和版本信息。
- 变异与畸变覆盖。

### 4.3 `packages/renderer-canvas`

只读取合法的 `MonsterSpec` 和素材目录，在 Canvas 2D 中完成确定性合成。渲染器不得自行抽取或替换特征。

### 4.4 `packages/asset-catalog`

保存主题、特征、部件清单、透明图、颜色遮罩、锚点、兼容骨架、层级、边界和校验哈希。目录独立版本化。

### 4.5 `packages/incubator-adapter`

把孵化器的蛋主题、种子、风险、语义特征和已有档案转换成核心输入；把完整结果投影回旧孵化器所需的 8 个主特征 ID。v0.1 提供适配代码和固定夹具测试，不直接改动孵化器工程。

## 5. 数据模型

### 5.1 视觉槽位

固定 14 个视觉槽位：

1. `bodyFrame`：体型。
2. `headShape`：头部。
3. `eyes`：眼睛。
4. `mouthShape`：嘴型。
5. `oralDetail`：牙齿或舌头。
6. `headAppendage`：耳朵、角或触角。
7. `arms`：手臂。
8. `legs`：腿脚。
9. `tail`：尾巴。
10. `extraAppendage`：翅膀或额外附肢。
11. `surfaceMaterial`：表皮材质。
12. `pattern`：纹样。
13. `colorScheme`：主题内的主色、辅色和点缀色排列。
14. `effect`：微光、孢子、残影等可视特效。

`headAppendage`、`tail`、`extraAppendage` 和 `effect` 可选中显式的 `none` 候选。无口、无足等情况同样以合法候选 ID 表示，不使用缺失字段表达。

### 5.2 语义槽位映射

| 孵化器语义槽 | 视觉来源 |
| --- | --- |
| 体型骨架 | `bodyFrame` |
| 附肢 | `arms`、`legs`、`tail`、`extraAppendage` |
| 头部与眼 | `headShape`、`eyes`、`headAppendage` |
| 口器 | `mouthShape`、`oralDetail` |
| 表皮材质 | `surfaceMaterial` |
| 纹样 | `pattern`、`colorScheme` |
| 性格气质 | 独立语义抽取，不占视觉槽位 |
| 异能怪癖 | 独立语义抽取，可提高 `effect` 候选权重 |

每个视觉部件可声明 `semanticTraitId` 和 `semanticPriority`。一个语义组存在多个候选时，选择最高优先级特征作为 `primaryTraitId`；相同优先级按固定槽位顺序决胜，其余进入 `detailTraitIds`。适配器向旧孵化器输出 8 个 `primaryTraitId`，完整 14 槽仍保留在扩展数据中。

### 5.3 `MonsterSpec`

```ts
interface MonsterSpec {
  schemaVersion: string;
  catalogVersion: string;
  rendererVersion: string;
  seed: string;
  themeId: "deep-sea" | "fungal" | "shadow";
  palette: {
    primary: string;
    secondary: string;
    accent: string;
  };
  slotRolls: Record<VisualSlotId, number>;
  visualSlots: Record<VisualSlotId, VisualSelection>;
  semanticTraits: Record<SemanticSlotId, {
    primaryTraitId: string;
    detailTraitIds: string[];
  }>;
  mutation: ModifierApplication | null;
  aberrations: ModifierApplication[];
}
```

`MonsterSpec` 是可复现结果的唯一真相源。锁定状态属于编辑会话而非生物本体，保存在本地工作区状态中；导入 `MonsterSpec` 时恢复生物并默认解锁全部槽位。

## 6. 确定性生成规则

### 6.1 子种子

每个视觉槽位使用独立子种子：

```text
hash(seed, themeId, slotId, rerollIndex)
```

局部重抽只递增目标槽位的 `rerollIndex`。无依赖关系的其他槽位保持不变。整只重抽产生新主种子，并将所有槽位重抽次数归零。

### 6.2 候选选择

每个槽位执行以下步骤：

1. 根据骨架兼容、硬性互斥和素材可用性过滤候选。
2. 以 70% 概率使用主题池、30% 概率使用全量池；主题池为空时确定性回退到全量池。
3. 在现有稀有度中按普通 70%、稀有 25%、传说 5%重新归一化后选择稀有度。
4. 在对应稀有度内应用条目基础权重、主题倍率和联动倍率。
5. 用槽位子种子完成加权抽取。
6. 生成完成后执行跨槽位完整校验。

v0.1 的正式目录只要求普通和稀有完整可用；核心算法从第一版开始支持传说等级。

### 6.3 依赖与局部重抽

规则依赖构成有向无环图。重抽父槽位时，只重新计算目标槽和未锁定的下游依赖槽位。锁定的下游槽位若变得不兼容，保留用户选择并产生阻断性诊断，不静默替换。

手动选择绕过随机权重，但不能绕过硬性互斥、骨架兼容和素材完整性检查。

### 6.4 变异与畸变

基础生物生成完成后再应用变异和畸变。结果同时保存基础选择和覆盖信息，保证可检查、可撤销和可复现。v0.1 仅提供少量样例，但数据结构与渲染顺序按完整机制设计。

## 7. 素材生产管线

### 7.1 美术规范

- 三分之四正面固定镜头，保持参考图的亲和构图。
- 圆润夸张比例、友善怪奇表情和柔和棚拍光。
- 统一相机高度、焦段、地面接触方向和主光方向。
- 工作画布 1024×1024；正式源素材保留 2048×2048 RGBA。
- 输出透明背景；地面阴影作为独立素材层。
- 主色、辅色遮罩与光影层分离，换色不得破坏体积感。

### 7.2 AI 辅助流程

1. 为每种骨架族锁定一套无特征或低特征母体。
2. 基于母体做单槽位局部改绘，不让各部件独立文生图。
3. 人工检查风格、视角、遮挡、光向和“怪而友善”的边界。
4. 抠图并拆分透明 WebP、颜色遮罩和必要的阴影高光层。
5. 标注骨架族、插槽、部件原点、层级、边界和预设缩放。
6. 通过自动组合与人工视觉验收后写入正式目录。

每个素材条目保留来源提示词哈希、母体版本和处理版本，便于追溯风格漂移。

### 7.3 骨架与锚点

v0.1 支持三个骨架族：

- 团絮／矮墩。
- 双足。
- 飘浮。

身体素材声明 `head`、`armLeft`、`armRight`、`legLeft`、`legRight`、`tail`、`wingLeft` 和 `wingRight` 等 socket。部件声明本地 origin。渲染时对齐 socket 与 origin，只允许目录中预先批准的缩放和镜像。

运行时不提供自由拖动。明显错位必须修正素材或兼容规则，禁止为某个种子增加渲染器硬编码补丁。

## 8. Canvas 渲染

固定图层顺序由后到前为：

1. 地面阴影。
2. 后侧附肢。
3. 躯干。
4. 表皮材质。
5. 纹样与配色。
6. 前侧附肢。
7. 头部。
8. 五官与头饰。
9. 前景特效。

渲染器对同一 `MonsterSpec` 必须生成相同像素缓冲区。PNG 为保证兼容性的必备输出；WebP 为减小体积的并列输出。若浏览器不支持 WebP 编码，JSON 与 PNG 仍可正常导出，并显示明确的能力提示。

## 9. 网页工作台

### 9.1 布局

- 顶栏：导入 JSON、导出 JSON、导出透明 PNG/WebP。
- 左栏：主题、种子、正常／变异／畸变状态和整只生成。
- 中央：实时生物预览、临时观察背景、目录版本和诊断摘要。
- 右栏：按形体、面部、附肢和表面分组的 14 个槽位。每行提供锁定、当前值、局部重抽和手动选择。

桌面优先；窄屏按“全局条件 → 预览 → 槽位列表”纵向重排。v0.1 不做移动端深度优化。

### 9.2 数据流

```text
UI command
  -> generator-core
  -> MonsterSpec
  -> schema and catalog validation
  -> renderer-canvas
  -> preview
  -> local workspace autosave
```

UI 不直接修改 `MonsterSpec` 内部字段。每次操作均转换为命令，由核心返回新结果和结构化诊断。

### 9.3 主题切换

切换主题时保留仍兼容的锁定槽位，重新生成未锁定槽位。与新主题或骨架不兼容的锁定槽位原样保留并标红，直到用户解锁、换件或恢复原主题；存在此类冲突时禁止正式导出。

## 10. 错误处理

### 10.1 阻断性错误

以下情况保留当前编辑状态、指出具体槽位并禁止正式图片和正式 JSON 导出：

- 必需槽位无合法候选。
- 手动选择或锁定项形成硬性互斥。
- 素材文件、遮罩、锚点或版本缺失。
- `MonsterSpec` Schema 不受支持。
- 目录校验失败。

系统不得静默替换部件。

### 10.2 降级性错误

- 图片编码或 Canvas 能力不足：仍允许导出合法 JSON；PNG 与 WebP 分别显示能力状态。
- 导入失败：在临时对象中完成解析和校验，失败时不修改当前作品。
- 旧目录版本：本地仍安装该版本时允许渲染并显示警告；版本不存在时作为阻断性错误处理。
- 单个图片加载失败：预览显示明确的缺件占位和素材 ID，不使用相似部件替代。

### 11.1 主题

- 深海。
- 菌沼。
- 幽影。

### 11.2 视觉内容

- 14 个视觉槽位各 3–5 个选项。

“约 50 组”是生产预算，不是导出合法性的模糊条件。正式发布前，素材目录必须通过必需槽位覆盖校验；可选槽位必须包含合法的 `none` 候选。

## 12. 测试策略

### 12.1 核心单元测试

- 固定种子生成固定结果。
- 局部重抽不改变无依赖槽位。
- 锁定槽位保持不变。
- 主题池 70/30 分支、稀有度和联动倍率符合配置。
- 互斥和骨架兼容规则生效。
- 14 个视觉槽位稳定投影为 8 个语义槽位。
- 变异与畸变保存基础值和覆盖值。

### 12.2 属性与统计测试

- 批量随机种子均在有限步骤内得到结果或结构化失败，不出现死循环。
- 每个主题的必需槽位均存在合法组合。
- 使用足够样本对主题分支和稀有度分布做容差统计检查。

### 12.3 素材目录校验

- ID 唯一，引用存在。
- 图片尺寸、透明通道和文件类型合法。
- 锚点位于允许边界内。
- 骨架兼容列表非空。
- 必需槽位覆盖完整，可选槽位具有 `none`。
- 互斥与联动引用指向有效 ID。

### 12.4 渲染回归

- 固定 `MonsterSpec` 的 RGBA 像素缓冲区哈希稳定。
- 1024×1024 与 2048×2048 导出尺寸、透明度和裁切正确。
- 图层遮挡、镜像和颜色遮罩使用黄金样例回归。

不使用编码后的 PNG/WebP 文件字节作为跨浏览器一致性依据，因为编码器元数据可能不同；比较解码后的像素缓冲区。

### 12.5 界面端到端测试

- 整只生成。
- 锁定后局部重抽。
- 手动选择和冲突阻断。
- 切换主题后兼容锁保留、不兼容锁报错。
- JSON 导出再导入后配方和像素结果一致。
- PNG/WebP 能力降级提示。

## 13. 性能与兼容目标

- 素材已缓存时，局部重抽到预览更新不超过 150ms。
- 1024×1024 图片导出不超过 2 秒。
- 连续重抽 100 次无持续性明显内存增长。
- 素材按主题懒加载，不要求首次下载全部目录。
- Chrome 与 Edge 桌面最新版作为正式验收环境。
- Firefox 与 Safari 保证基本生成和 PNG 导出；WebP 编码按能力检测降级。

## 14. 人工视觉验收

发布前连续随机生成 20 只生物，覆盖三个主题和三种骨架族。逐只检查：

- 无明显断肢、悬空、穿插、接缝或错误遮挡。
- 眼睛、嘴巴、附肢与主体视角一致。
- 光源、阴影、材质和主题色板统一。
- 每只都“怪而友善”，不进入恐怖谷。
- 三个主题可辨识，同时允许少量跨主题组合。

任一生物出现明显拼接问题时，修正素材、锚点或兼容规则后重新开始 20 只连续验收。

## 15. 完成定义

v0.1 只有同时满足以下条件才视为完成：

1. 所有核心、属性、目录、渲染和端到端测试通过。
2. `MonsterSpec` JSON 往返后配方和解码像素完全一致。
3. 素材目录无缺失引用、非法锚点或必需槽位覆盖缺口。
4. 连续 20 只人工视觉验收通过。
5. 孵化器适配夹具能稳定输出旧接口需要的 8 个主特征 ID。
6. Chrome/Edge 性能目标通过，Firefox/Safari 的 PNG 降级路径可用。

## 16. 风险与缓解

| 风险 | 缓解措施 |
| --- | --- |
| AI 素材风格漂移 | 锁定母体后局部改绘；保留来源版本；人工筛选 |
| 部件接缝与穿插 | 骨架族、socket/origin、兼容矩阵、自动组合和连续 20 只验收 |
| 生成器与孵化器规则漂移 | 共享 `generator-core`，适配器只做边界转换 |
| 局部重抽牵连全部结果 | 每槽独立子种子与依赖图，只重算未锁定下游 |
| 目录升级破坏旧生物 | `schemaVersion`、`catalogVersion`、`rendererVersion` 三重版本化 |
| 素材体积过大 | 按主题懒加载、运行时 WebP、保留离线 2048 源文件 |
| 浏览器导出能力差异 | PNG 必备，WebP 能力检测并明确降级 |

## 17. 后续阶段

书面规格获得最终确认后，下一步只创建实施计划。实施计划将拆分为仓库骨架、核心 Schema 与 PRNG、目录校验器、渲染器、网页工作台、适配器、素材垂直切片和验收自动化等独立任务。完整 10 主题和 103 条特征在 v0.1 验证通过后另行规划。
