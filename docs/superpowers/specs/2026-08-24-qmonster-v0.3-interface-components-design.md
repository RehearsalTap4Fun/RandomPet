# QMonster Creator v0.3 接口化结构组件设计

- 日期：2026-08-24
- 状态：设计已确认，待用户审阅书面规格
- 基线分支：`feature/qmonster-v0.1`
- 前置规格：`docs/superpowers/specs/2026-08-24-qmonster-composition-coherence-design.md`
- 目标目录版本：`0.3.0`
- 目标渲染器版本：`0.3.0`

## 1. 背景与问题结论

v0.2 已解决随机预算、层级挂点、面部保护、版本隔离和机器验收，但两轮完整生物联系表均未通过用户美术验收：

1. 第一轮把头、躯干和四肢直接叠在同一区域，缺少上下和侧向结构关系；拒绝联系表 SHA-256 为 `7cad7a5c551fcd7e1f510fd84fd1f46b47e921e36e9a4ae5822000155ea6b3bc`。
2. 第二轮通过真实 alpha 轮廓把头、手臂和腿放到正确相对位置，但组件边缘仍像互不相关的裁片，缺少颈部、肩部和髋部的体积过渡；拒绝联系表 SHA-256 为 `36bfca5567a6470b27fdf5cd1cc3a6c28bbbf61a532bee22159e595d4563b34f`。

根因不是挂点求解错误。v0.2 的 renderer 能准确对齐 socket 与 origin；问题在素材生产契约：结构素材来源于完整角色图的裁切或旧式单件图，只描述“可见轮廓”，没有描述连接端、进入方向、材质过渡和前后遮挡。继续调整坐标只能改变裁片位置，不能让裁片成为同一个生物体。

本设计将结构素材从“透明图片 + 锚点”升级为“rig 专属结构变体 + 标准接口轮廓 + 柔性过渡组织”。这是架构替换，不是 v0.2 坐标补丁。

## 2. 已确认的产品决策

| 决策 | 结论 |
| --- | --- |
| 结构体系 | 采用接口化骨架组件，继续保留头、躯干和四肢的独立随机能力 |
| 接缝视觉 | 使用自动染色、自动匹配材质的柔性过渡组织；不暴露玩具式硬套环 |
| 兼容粒度 | 同一造型按 `blob`、`biped`、`floating` 分别制作 rig 接口变体；禁止跨 rig 素材回退 |
| 素材范围 | 重做 `bodyFrame`、`headShape`、`arms`、`legs`、`tail`、`extraAppendage`；保留已认可的五官、口腔细节、头饰、颜色、纹理和效果 |
| 落地方式 | 采用混合式接口契约：组件提供接口数据，少量预制软组织桥由 renderer 受限变形、染色和合成 |
| 版本边界 | v0.1、被拒绝的 v0.2 保持精确只读；新架构使用 catalog/renderer `0.3.0`，不得静默迁移旧标本 |
| 生产顺序 | 先完成 biped 垂直切片并由用户批准，再扩展全部 rig 和素材 |

## 3. 目标与非目标

### 3.1 目标

1. 任意被允许的头、躯干和四肢组合都呈现为一个连续生物体，而不是相邻或重叠的透明裁片。
2. 颈部、肩部、髋部、尾根和额外附肢根部具备明确的接入方向、宽度、深度和遮挡关系。
3. 同一结构造型可跨三个 rig 保持视觉身份，但每个 rig 拥有独立接口变体。
4. 柔性过渡组织能够匹配两侧颜色和基础材质，同时受到严格形变上限约束。
5. 缺少变体、接口不兼容或连接失败时，在候选选择或渲染阶段阻塞，绝不输出断开的生物。
6. 保留 14 个视觉槽位、8 个语义槽位、确定性种子、锁定、局部重抽、手选和孵化器投影能力。

### 3.2 非目标

- 不引入实时 3D、骨骼动画或物理模拟。
- 不为每一对头和躯干生产专属连接图，避免素材数量按组合平方增长。
- 不重做已通过用户判断的眼睛、嘴、口腔细节和头部装饰造型。
- 不用模糊、羽化整张图片或扩大重叠面积来掩盖接缝。
- 不允许针对固定 seed、具体 part ID 或验收联系表写坐标特判。
- 不把被拒绝的 v0.2 证据改写为批准记录。

## 4. 方案比较与选择

### 4.1 纯程序桥接

根据两端 alpha 轮廓直接生成连接形状，素材成本最低，但缺少美术控制，容易产生橡皮筋拉伸、方向不一致和材质塑料化。该方案不采用。

### 4.2 完全预制连接件

为每一对结构组件绘制专属颈部、肩部或髋部，效果可控，但素材数量随组合爆炸，并破坏自由随机的核心目标。该方案不采用。

### 4.3 混合式接口契约

每个结构变体提供标准连接端；每个 rig 与接口类别提供少量中性软组织桥。renderer 只在受限范围内扭曲桥接图，并使用两侧材质采样进行染色。这既保留组合能力，也把接缝外观纳入美术生产。该方案为最终选择。

## 5. 版本与系统边界

```text
generator-core
  选择 exact-rig 结构变体并排除接口不兼容候选
        ↓
asset-catalog v0.3.0
  描述结构图层、receiver/plug 接口、过渡桥和形变限制
        ↓
renderer-canvas v0.3.0
  求解接口 → 生成过渡层 → 合成结构 → 合成非结构特征 → 测量
        ↓
creator-web
  展示结果、阻塞错误和版本化只读查看器
```

版本注册表必须精确安装 `0.1.0`、`0.2.0`、`0.3.0`。编辑工作台只有在 v0.3 垂直切片和完整验收获用户批准后才切换默认版本。v0.1/v0.2 spec 继续使用各自 renderer/catalog，不做字段补齐、接口猜测或资产回退。

## 6. 结构组件契约

### 6.1 结构槽位

以下槽位使用 v0.3 接口契约：

```text
bodyFrame
├─ headShape
├─ arms
├─ legs
├─ tail
└─ extraAppendage
```

`bodyFrame` 提供 receiver；其余结构槽位提供 plug。`headShape` 继续为 `eyes`、`mouthShape` 和 `headAppendage` 提供安全区和内部挂点。

### 6.2 接口标识

固定接口语义如下：

| 接口 | Receiver | Plug | 主要方向 |
| --- | --- | --- | --- |
| `neck` | `bodyFrame` | `headShape` | 头在躯干上方 |
| `shoulderLeft` / `shoulderRight` | `bodyFrame` | `arms` 左/右节点 | 肢体从躯干两侧接出 |
| `hipLeft` / `hipRight` | `bodyFrame` | `legs` 左/右节点 | 腿从躯干下方承重 |
| `tailRoot` | `bodyFrame` | `tail` | 尾部从后侧或侧下方接出 |
| `extraLeft` / `extraRight` | `bodyFrame` | `extraAppendage` 节点 | 翼、鳍、触手按定义从侧后方接出 |

### 6.3 数据模型

设计目标类型如下；实施计划可调整命名，但不得削弱字段语义：

```ts
type ConnectorRole = 'receiver' | 'plug'
type ConnectorClass = 'neck' | 'shoulder' | 'hip' | 'tail' | 'extra'

interface ConnectorProfile {
  id: string
  role: ConnectorRole
  connectorClass: ConnectorClass
  rigId: RigId
  origin: Point2D
  tangent: Point2D
  outwardNormal: Point2D
  width: number
  depth: number
  contourMaskPath: string
  foregroundMaskPath: string
  backgroundMaskPath: string
  materialSampleRegion: Rect
  warpLimits: {
    widthRatio: { min: number; max: number }
    depthRatio: { min: number; max: number }
    rotationDegrees: { min: number; max: number }
  }
}

interface StructuralVariant {
  rigId: RigId
  assetPath: string
  pngPath: string
  connectors: ConnectorProfile[]
  faceSafeZones?: Rect[]
  featureSockets?: Record<string, Point2D>
}

interface TransitionBridgeDefinition {
  id: string
  rigId: RigId
  connectorClass: ConnectorClass
  neutralAssetPath: string
  neutralPngPath: string
  frontMaskPath: string
  backMaskPath: string
  materialFamilies: string[]
}
```

所有路径和哈希继续接受生产验证。connector mask、front/back mask 和 bridge 资源均为生产资源，不得依赖运行时文件名猜测。

### 6.4 Exact-rig 变体

一个视觉造型可以在多个 rig 中存在，但每个 rig 都必须提供独立 `StructuralVariant`。例如 `head_mushroom_cap` 的三个变体共享造型身份和强度标签，但颈根宽度、接入角度、遮罩和面部安全区分别制作。

如果选定 rig 没有对应变体，generator 在候选阶段排除该 part。renderer 不得使用其他 rig 变体，也不得按比例强行适配。

## 7. 柔性过渡组织

### 7.1 求解流程

对每一对 receiver/plug：

1. 验证双方 `rigId` 和 `connectorClass` 精确一致。
2. 将 plug 的 origin、tangent 和 outward normal 对齐 receiver。
3. 计算宽度比、深度比和旋转量；任一值超出双方限制即判不兼容。
4. 选择同 rig、同接口类别的中性 bridge。
5. 使用受限的二维网格或 Bézier 变形，把 bridge 的两端贴合双方 contour mask。
6. 从 receiver 和 plug 的 `materialSampleRegion` 采样基础色与材质强度，沿连接方向进行双向混合。
7. 按 `back bridge → child/body structural layers → front bridge` 的明确顺序合成，隐藏根部而不吞没组件主体。
8. 扩展最终结构 alpha mask，供表皮、纹理和边界指标共同使用。

renderer 只能执行 catalog 已声明的变形，不得根据 part ID、seed 或图片内容临时选择坐标。

### 7.2 材质策略

首版只支持当前需要的三个基础材质家族：短绒、蘑菇绒面和软胶/皮肤。bridge 使用中性灰度明暗资产，通过两侧采样染色；表皮和纹理随后裁剪到包含 bridge 的结构联合 mask。

如果两侧材质家族没有共同 bridge 支持，组合在生成阶段不可选。不得用全图模糊或统一颜色覆盖解决不兼容。

### 7.3 前后遮挡

每个接口同时提供 foreground/background mask。肩部、髋部通常让根部后半藏入躯干，前半由过渡组织覆盖；颈部根据 head variant 决定头在前或躯干在前。遮挡规则属于接口数据，不属于全局槽位常量。

## 8. 非结构特征复用

以下槽位保留 v0.2 已认可素材：

```text
eyes
mouthShape
oralDetail
headAppendage
surfaceMaterial
pattern
colorScheme
effect
```

它们必须重新锚定到 v0.3 结构节点：

- `eyes`、`mouthShape` 和 `headAppendage` 使用 head variant 的 feature sockets 与 face safe zone。
- `oralDetail` 继续依赖 mouth 内部接口。
- `surfaceMaterial`、`pattern` 和 `colorScheme` 裁剪到“结构组件 + bridge”的联合 alpha。
- `effect` 继续执行 protect-face，并不得制造独立第二轮廓。

保留素材指保留视觉内容，不代表复用 v0.2 的坐标或兼容性声明。

## 9. 素材生产流程

### 9.1 新源树

v0.3 使用独立源和产物：

```text
asset-source/v0.3.0/
packages/asset-catalog/catalog/v0.3.0/
packages/asset-catalog/assets/v0.3.0/
packages/asset-catalog/audit/v0.3.0/
packages/asset-catalog/review/v0.3.0/
```

v0.2 不作为可修改模板。可以引用其合格非结构素材，但 v0.3 source index 必须记录复制来源、原哈希和新版本哈希。

### 9.2 结构素材要求

每个结构变体必须：

1. 使用对应 rig 的接口 guide 作为生产参考。
2. 在透明 RGBA 中保留明确的连接桩或进入轮廓，不能只生成独立完整轮廓。
3. 提供 contour/front/back/material masks。
4. 通过透明抽取、尺寸、哈希、接口覆盖和变形范围检查。
5. 在无五官、无纹理的中性结构联系表中先证明连接质量。

图像生成只用于真正需要重做的结构组件，并使用当前会话的内置图像生成工作流。每个生产输出必须进入 v0.3 workspace 源树，不能只留在默认生成目录。

### 9.3 垂直切片

批量生产前先完成 biped：

- 2 个 `bodyFrame`
- 2 个 `headShape`
- 2 组 `arms`
- 2 组 `legs`
- neck、shoulder、hip 三类 bridge

穷举 `2 × 2 × 2 × 2 = 16` 个结构组合。预览使用中性配色，不加入表皮、纹理、效果和异常修饰，避免非结构内容掩盖接缝。只有用户明确批准这 16 个组合后，才能扩展 blob、floating 和全部结构目录。

## 10. 生成与错误处理

generator 在选择结构 part 前执行静态兼容性检查：exact rig variant、接口类别、宽度/深度比和 bridge 材质家族。确定性候选 trace 必须记录被排除原因。

阻塞诊断至少包括：

```text
CONNECTOR_VARIANT_MISSING
CONNECTOR_PROFILE_INVALID
CONNECTOR_WARP_EXCEEDED
CONNECTOR_BRIDGE_MISSING
CONNECTOR_COMPOSITE_FAILED
STRUCTURE_DISCONNECTED
```

这些错误都阻止预览提交和导出。局部重抽只能从兼容候选中选择；手选不兼容结构 part 时保留当前有效选择并给出错误，不生成断裂的临时标本。

## 11. 验收门禁

### 11.1 机器门禁

连接求解和最终 alpha 至少满足：

- exact rig 和 connector class 匹配率 100%。
- 宽度、深度、旋转均在 catalog 双方声明范围内。
- bridge 对 receiver 和 plug 的有效覆盖率分别不低于 90%。
- 结构联合 alpha 的最大连通分量占非效果结构 alpha 不低于 99%。
- 接口中心线上的透明间隙不超过 2 个 1024 输出像素。
- appendage 主体不得整体吞入躯干；每个手臂和腿至少 65% 的可见 alpha 位于躯干 alpha 外。
- 眼睛和嘴继续满足 inside ≥ 0.8、visible ≥ 0.85。
- 不得出现 render diagnostics、越界、第二主体轮廓或跨版本资源。

阈值必须针对接口类别和输出分辨率统一计算，不能针对 seed 或 part ID 放宽。

### 11.2 垂直切片美术门禁

用户在原尺寸和 256×256 下审查 16 个 biped 组合：

- 头和躯干之间有连续体积，不像球体落在另一个球体上。
- 手臂从肩部生长，不像贴在躯干正面或悬浮在侧面。
- 腿从髋部向下承重，不像另一个完整组件顶住身体。
- bridge 不呈现套圈、贴片、绳索或橡皮筋拉伸感。
- 毛发或软胶的明暗方向在接缝两侧连续。
- 每个结果仍保持友好怪奇风格和单一主体轮廓。

任一组合失败时，修复接口或结构素材并重新生成完整 16 组合；不得删除失败组合。

### 11.3 完整目录门禁

垂直切片批准后才执行：

1. 三 rig 结构矩阵审查。
2. 10,000 seed 预算和可选 none 分布。
3. 固定 20 + first-hatch 完整生物联系表。
4. golden、E2E、性能、双旧版回归和 exact-version 验证。
5. 用户最终完整生物批准记录。

用户批准记录仍绑定当前联系表和 manifest 的 SHA-256。v0.2 的两次拒绝记录只作为 audit 证据，不能满足 v0.3 门禁。

## 12. 测试策略

### 12.1 单元测试

- Zod/schema：接口字段、mask/hash、warp limits、exact rig variant。
- connector solver：位置、切线、法线、宽度、深度和旋转。
- bridge warp：固定输入输出、边界拒绝、source spec 不变。
- material sampling：两侧颜色混合、材质家族不兼容拒绝。
- candidate filter：缺变体和超形变 part 不进入候选池。

### 12.2 集成测试

- 使用真实 alpha mask 的 neck/shoulder/hip 连通性。
- front/back mask 的合成顺序和接缝覆盖。
- 非结构特征重新锚定、face protection 和联合结构裁剪。
- v0.1、v0.2、v0.3 exact registry 与无 fallback。
- 16 组合 biped 垂直切片固定回归。

### 12.3 浏览器与发布测试

- Chromium 解码 RGBA golden，而不是编码 PNG hash。
- 完整生成、锁定、重抽、手选、导出和旧版只读查看。
- 100 次 warmed reroll p95 ≤ 150ms；PNG 导出 ≤ 2000ms；bridge/cache 不单调增长。
- 覆盖率连续两次从同一 clean baseline 通过。

## 13. 迁移与拒绝证据

当前 Task 7 的验收基础设施、性能优化和测试工具可在实现计划中拆分为独立 checkpoint；它们不等于 v0.2 美术批准。v0.2 的两次联系表 hash、用户反馈和根因诊断必须写入 audit/rejection 记录。

在 v0.3 垂直切片获批之前：

- creator 默认版本保持当前已提交状态，不宣称 v0.2 发布完成。
- 不创建 v0.2 `decision: approved` 记录。
- 不把 v0.2 rejected sheet 注册为 golden 或发行证据。
- 不批量生成三 rig 新结构素材。

## 14. 完成定义

v0.3 只有同时满足以下条件才算完成：

1. biped 16 组合结构切片获用户批准。
2. 三 rig 的结构素材和 bridge 全部通过 production validation。
3. 固定完整生物集合的每个接缝、面部和轮廓机器指标通过。
4. v0.1/v0.2 精确只读行为和 goldens 保持。
5. 用户批准当前 v0.3 完整生物联系表，且批准记录 hash 与文件一致。
6. typecheck、Vitest、coverage、build、browser goldens、E2E、performance、catalog validation 和最终 verify 全部 exit 0。
