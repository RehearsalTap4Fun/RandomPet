# QMonster v0.9 原子骨架与定域素材设计

日期：2026-09-09

状态：三项架构决策已在会话中确认，待用户审阅本文档

## 1. 目标

发布 `catalog 0.9.0`，从素材生产结构上消除头、躯干、四肢、尾巴、纹理、五官、口腔与附件之间反复出现的错位、覆盖、悬浮和接缝问题。

本版本不再把“任意透明图层＋运行时定位＋裁剪”视为组件系统。它采用：

1. 不可拆分的完整动物骨架；
2. 在完整母版上下文中定域制作的 trait；
3. 不允许 trait 自定义的固定遮挡图；
4. 固定画布、固定像素位置、无 transform 的运行时资产；
5. 失败关闭但不承担视觉修复的发布门禁。

设计原则借鉴 CryptoKitties：先固定物种、姿势和可识别轮廓，再在受控表型槽位中制造差异。不推断或复制其未公开实现，不复用其美术、品牌或素材。

## 2. 已确认决策

1. 猫的头、颈、躯干、四肢和完整尾巴构成一个 `SkeletonFamily`，这些结构不再作为可交叉随机的独立图片部件。
2. 普通和稀有外观使用主骨架；传说级允许切换到另一套完整 `SkeletonFamily`。骨架变化必须整套发布，不能把一个家族的头、身体、四肢或尾巴装到另一个家族上。
3. 所有 trait 必须在完整、已批准的母版上下文中定域制作；禁止脱离生物上下文生成局部素材后再移动到母版。
4. `feline-sit-v2` 母版不包含眼窝、眼白、虹膜、瞳孔或高光，只保留连续脸部毛发、鼻子、口鼻体块和完整骨架。
5. `eyes` 是完整的成对 trait；左右眼共享一个 trait ID、稀有度和重掷生命周期。
6. 颜色和纹理属于整个骨架表面的材质层，不能产生独立轮廓或拆成头、躯干、四肢、尾部四套自由叠加图。
7. 嘴型拥有自己的局部 `oralSocket`；牙齿和舌头必须先兼容嘴型，再进入口腔层。
8. 大型轮廓变化，包括尾形、头型、体型和肢体比例，只能包含在完整骨架家族中。角、耳饰、鬃毛和项圈等不承担主体解剖连接的小型附属物，才可通过预定义 `MasterAttachmentInterface` 制作。
9. renderer 使用固定 `CompositionGraph`；trait 不能提交 `zIndex`、transform、裁剪或自定义混合顺序。
10. 每个正式外观 trait 槽位的普通、稀有、传说类型数量均为 `8:4:1`。`skeletonFamily` 是先于外观 trait 的完整结构选择，不套用“每档 8/4/1 个素材”的库存规则；首版只提供一个主骨架和一个传说骨架。
11. 自动化不得通过反复主观审核重抽样本。最终固定 seed 批次只用于用户验收。
12. 新方案发布为独立版本；`0.8.0 / feline-sit-v1` 保持只读并继续按历史路径复现。
13. 所有可选附属物使用封闭 `shapeClass` 枚举和素材白名单；新增素材只在完整母版中批准一次并冻结内容哈希，运行时只能解析已批准哈希。

## 3. 为什么旧方案仍不足

上一版 `PoseTemplate＋局部 trait 编译` 虽然建立了锚点，但仍允许先制作任意局部图片，再依赖仿射映射、裁剪和几何检测把它放回生物。它仍可能产生：

- 纹理沿旧路径作为独立图层悬浮；
- 坐标正确但层级错误，导致躯干盖头或五官盖住其他结构；
- 先裁剪后检测，使严重偏移的素材只剩小片仍通过门禁；
- 嘴型变化后，固定于全局的牙齿和舌头脱离口腔；
- 大型附件只用少量像素接触身体也被判为已连接；
- 不同仿射、插值和舍入实现产生不同像素结果。

因此 v0.9 不再将锚点转换作为主要方案。位置在素材制作时已经确定；验证只拒绝违反合同的资产，不负责把错误资产修好。

## 4. 版本身份

v0.9 使用唯一、完整的版本元组：

```ts
const V09_VERSION_TUPLE = {
  schemaVersion: '0.4.0',
  catalogVersion: '0.9.0',
  rendererVersion: '0.9.0',
} as const
```

首个实例为：

```ts
const FELINE_SIT_V2 = {
  archetypeId: 'feline',
  speciesRigId: 'feline-sit-v2',
  skeletonPoolId: 'feline-sit-v2-pool',
} as const
```

`MonsterSpec 0.4.0` 必须保存完整版本元组及实际选中的 `speciesRigId`、`skeletonFamilyId`、`assemblyTemplateId`。旧 spec 不补写、猜测或迁移这些字段：

| 输入 | 必须字段 | 路由 |
|---|---|---|
| v0.8 历史 spec | 历史 `0.3.0/0.8.0/0.8.0` 字段 | 原 v0.8 renderer/catalog |
| v0.9 新 spec | `0.4.0/0.9.0/0.9.0`＋三个结构 ID | v0.9 renderer/catalog |
| 混合、缺失或未知元组 | 不接受 | `VERSION_TUPLE_MISMATCH` |

creator、catalog report、CLI 和 incubator 共同读取同一个可变指针文件 `active-release.json`；该文件只保存目标 release manifest 的内容哈希。切换默认版本只原子更新此指针，内容寻址的 release manifest 本身不可修改；显式声明历史版本的 spec 不受默认值变化影响。

```ts
type V09TraitSlotId =
  | 'bodyColor'
  | 'surfacePattern'
  | 'surfaceTexture'
  | 'forepawDetail'
  | 'hindpawDetail'
  | 'tailSurface'
  | 'eyes'
  | 'mouthShape'
  | 'oralDetail'
  | 'headAppendage'
  | 'extraAppendage'
  | 'effect'

interface MonsterSpecV09 {
  schemaVersion: '0.4.0'
  catalogVersion: '0.9.0'
  rendererVersion: '0.9.0'
  seed: string
  speciesRigId: 'feline-sit-v2'
  skeletonFamilyId: string
  assemblyTemplateId: string
  skeletonSelection: {
    class: 'base' | 'legendary'
    candidateId: string
    roll: number
  }
  visualSlots: Record<V09TraitSlotId, {
    traitId: string
    rarity: 'common' | 'rare' | 'legendary'
    roll: number
  }>
}
```

`skeletonSelection` 使用独立 seed domain。首版池中主骨架权重为 `8`、传说骨架权重为 `1`；它没有“稀有骨架”占位，也不伪造 8/4/1 个骨架素材。十二个 `V09TraitSlotId` 各自拥有 8 个普通、4 个稀有、1 个传说 trait。旧的 `bodyFrame`、`headShape`、`arms`、`legs`、`tail` 不再表示可替换结构：前两者由完整骨架承担，后三者拆为不会改变轮廓的表面细节槽位。

`active-release.json` 的解析只有一个共享入口：先在受控 catalog 根中按哈希定位并验证 release manifest，再从 manifest 取得 schema、catalog、renderer、species rig、skeleton pool 和模板资源。网页不得自行拼路径或用“最高版本”猜测默认版本。

## 5. 原子骨架

### 5.1 通用合同

```ts
interface SkeletonFamilyV1 {
  schemaVersion: 'qmonster-skeleton-family-v1'
  skeletonFamilyId: string
  skeletonClass: 'base' | 'legendary'
  structuralShapeClasses: StructuralShapeClass[]
  archetypeId: string
  poseId: string
  speciesRigId: string
  canvas: { width: 2048; height: 2048 }
  neutralMaster: PngResourceRef
  materialMap: PngResourceRef
  fixedOccluderMasks: Record<string, PngResourceRef>
  assemblyTemplateId: string
}

interface SkeletonPoolV1 {
  schemaVersion: 'qmonster-skeleton-pool-v1'
  skeletonPoolId: string
  candidates: [
    { skeletonFamilyId: string; skeletonClass: 'base'; weight: 8 },
    { skeletonFamilyId: string; skeletonClass: 'legendary'; weight: 1 },
  ]
}
```

这是跨物种通用 schema；`feline-sit-v2-core` 只是数据实例，不是 TypeScript 字面量限制。`skeletonClass` 表示结构池身份，不等同于某个外观 trait 的稀有度。

### 5.2 猫骨架内容

主骨架 `feline-sit-v2-core` 和传说骨架 `feline-sit-v2-legendary-01` 都必须是一只完整、连续、可独立识别为猫的中性母版：

- 头、颈、躯干、前后肢和完整尾巴已经正确连接；
- 主轮廓、接地线和姿势被冻结；
- 脸部没有预制眼窝或眼睛；
- 鼻子与口鼻体块保留，用于维持猫脸识别；
- `materialMap` 标出全身毛发、鼻子、肉垫等材质归属；
- 固定 occluder 是 alpha mask，不包含任何颜色或某个具体 trait 的外观。合成时它从已经应用颜色、图案和纹理的骨架表面重放像素，因此不会出现中性色补丁。

结构差异不再来自独立 `head/body/arms/legs/tailRoot` 图片。首版只有一套主骨架和一套传说骨架；传说骨架可以改变整体比例、头型、耳型或尾形，但必须仍能由完整母版单独识别为猫。它不是在主骨架上追加的结构覆盖层。

`skeletonFamily` 是生成流程的第一阶段结构选择，不计入十二个正式外观 trait 槽位。随机器选定完整骨架后，只能从 `skeletonFamilyId` 完全相同的 sealed trait projection 中选择其他槽位。

一个语义 trait ID 可以为两个骨架家族分别制作投影，但每个投影都必须在对应完整母版上独立定域制作和批准，不能靠运行时变换复用。发布门禁要求两个骨架都具有完整的逐槽 `8:4:1` 可达池；缺少投影的骨架不得进入 active catalog。

### 5.3 确定性选择顺序

1. 使用 `seed + /skeleton` 的独立随机域按 `8:1` 选择主骨架或传说骨架。
2. 固定 `skeletonFamilyId` 和对应模板；后续任何槽位不得切换骨架。
3. 每个正式外观槽位使用 `seed + /slot/<slotId>` 的独立随机域，先按普通、稀有、传说 `8:4:1` 选择稀有度，再在该稀有度的八、四或一个可达 trait 中等概率选择。
4. 每个 trait ID 解析为当前骨架专用的 sealed projection；缺少投影时整次生成失败，不换 trait、不换 seed。
5. `mouthShape` 解析完成后再派生口腔兼容池。关闭嘴固定使用 `oral-none`；其他嘴型仍按该兼容池的 `8:4:1` 清单选择。

锁定或单槽重掷只推进对应随机域的 roll 计数；骨架重掷会使全部外观投影重新解析，因此作为整只生物重掷处理，不能在保留旧骨架像素的情况下只替换 `skeletonFamilyId`。

## 6. AssemblyTemplate：设计侧约束

```ts
interface AssemblyTemplateV1 {
  schemaVersion: 'qmonster-assembly-template-v1'

}

    authoringZone: PngResourceRef
    parentMouthTraitIds: string[]
  }>
  closedMouthSentinel: 'oral-none'
}

type EmbeddedSlotTemplate = EyePairSlotTemplate | MouthSlotTemplate | OralDetailSlotTemplate

interface AttachmentSlotTemplate {
  kind: 'attachment'
  slotId: 'headAppendage' | 'extraAppendage'
  attachmentInterface: MasterAttachmentInterfaceV1
}

interface TargetedEffectSlotTemplate {
  kind: 'targetedEffect'
  slotId: 'effect'
  targetId: string
  authoringZone: PngResourceRef
  compositionNode: 'targetedEffect.underlay' | 'targetedEffect.overlay'
}

interface AmbientEffectSlotTemplate {
  kind: 'ambientEffect'
  slotId: 'effect'
  zoneId: 'background' | 'foreground'
  authoringZone: PngResourceRef
  compositionNode: 'backgroundEffect' | 'foregroundAmbientEffect'
}

type EffectSlotTemplate = TargetedEffectSlotTemplate | AmbientEffectSlotTemplate
```

`AssemblyTemplate` 不在运行时计算位置。它是生产工具加载的锁定工作台，规定哪些像素允许被修改、组件必须提供哪些层、以及这些层进入固定遮挡图的哪个节点。

所有 authoring mask、母版结构接口、口腔 socket、固定 occluder 和层级图都绑定同一完整模板哈希。模板不能引用画布外坐标，也不能包含运行时 transform。这里的“结构接口”不是历史版本的视觉锚点：它没有位置求解能力，只描述已经在完整母版固定坐标中制作好的隐藏重叠根、允许延伸区域和固定遮挡归属。

所有 zone、stencil、material map 和 occluder mask 都是二值 2048×2048 RGBA8 PNG：有效像素 alpha 必须为 255，无效像素必须为 0，RGB 固定为 0。工具不得使用灰阶 alpha 阈值自行解释边界。

## 7. Trait 类型

所有 trait bundle 都继承同一基础身份，不能脱离骨架和已批准模板单独存在：

```ts
interface TraitBundleBaseV1 {
  traitId: string
  rarity: 'common' | 'rare' | 'legendary'
  skeletonFamilyId: string
  assemblyTemplateId: string
  assemblyTemplateSha256: string
  fullContextPreview: PngResourceRef
}
```

### 7.1 表面材质

```ts
interface SurfaceTraitBundleV1 extends TraitBundleBaseV1 {
  kind: 'surface'
  slotId:
    | 'bodyColor'
    | 'surfacePattern'
    | 'surfaceTexture'
    | 'forepawDetail'
    | 'hindpawDetail'
    | 'tailSurface'
  materialOperation: JsonResourceRef
}

interface MaterialOperationV1 {
  schemaVersion: 'qmonster-material-v1'
  ownerMaterialId: string
  colorMap?: PngResourceRef
  colorLut?: number[]
  alphaPolicy: 'preserve-skeleton-alpha'
  blendMode: 'replace-color' | 'multiply' | 'overlay'
}
```

表面 trait 通过 `materialMap` 工作：

- `bodyColor` 对全身毛发材质应用版本化色彩映射；
- `surfacePattern` 与 `surfaceTexture` 是在完整母版上制作的全身连续表面操作；
- `forepawDetail`、`hindpawDetail` 与 `tailSurface` 只能改变对应材质分区内的颜色、纹样或微表面，不能改变爪或尾巴轮廓；
- 它们不能写入非 owner material，也不能增加母版轮廓外 alpha；
- 头、躯干、四肢和完整尾巴共享一次表面操作，因此不存在独立贴图之间的接缝。

生产工具在编辑阶段锁死非 owner 像素。发布器不会把越界图案裁回身体；发现越界资产时直接拒绝。

`materialMap` 的 R 通道保存由模板内 `materialRegistry` 冻结的 8-bit material index，G/B 固定为 0；主体内 A=255、主体外 A=0。owner 区域以 `R === materialIndex && A === 255` 精确判定，不使用颜色距离或阈值。`colorLut` 若存在必须恰好包含 256 个 RGBA8 条目。混合与舍入由 renderer 0.9.0 固定为 sRGB、预乘 alpha、round-half-up；不同实现必须通过逐像素黄金测试。

### 7.2 成对眼睛

```ts
interface EyePairTraitBundleV1 extends TraitBundleBaseV1 {
  kind: 'eyePair'
  slotId: 'eyes'
  underlay: PngResourceRef
  content: PngResourceRef
}
```

眼睛必须在无眼窝完整猫母版上定域制作：

- `underlay` 只包含中性的接触阴影和边缘过渡；
- `content` 同时包含左右眼球、虹膜、瞳孔和高光；
- 左右眼不能拆成两个 trait，也不能单独变换；
- 两个美术层均为 2048×2048 原位 PNG；
- 生产工具只允许修改固定 eye-pair authoring zone；
- 导出后不重新定位、缩放、旋转或镜像。

眼缘遮挡 mask 只由 `AssemblyTemplate` 持有，trait 无权提交或改写。renderer 使用它重放已经完成颜色与纹理处理的脸部表面像素，把眼睛边缘压入毛发；因此眼睛 trait 不需要烘焙某一种固定肤色，也不会像贴纸浮在脸上。

### 7.3 嘴与口腔

每个 `mouthShape` 是一个父组件：

```ts
interface MouthTraitBundleV1 extends TraitBundleBaseV1 {
  kind: 'mouth'
  slotId: 'mouthShape'
  oralSocketClass: string
  back: PngResourceRef
  oralSocketMask: PngResourceRef
  front: PngResourceRef
}

interface OralDetailTraitBundleV1 extends TraitBundleBaseV1 {
  kind: 'oralDetail'
  slotId: 'oralDetail'
  projections: Record<string, PngResourceRef>
}
```

`oralDetail` 声明自己支持的 `oralSocketClass`，并为每个支持的 class 提供在完整母版上下文中制作的固定位置投影。组合顺序永远是：

```text
mouth.back → oralDetail → mouth.front → mouth.edgeOcclusionReplay
```

这里的 `oralSocketClass` 只是“张口空间是否兼容”的封闭类别，不包含锚点、坐标或 transform；口腔投影已经处在对应完整母版的最终像素位置。

随机器只从当前嘴型的兼容口腔池中选择。关闭且不暴露口腔的嘴型必须选择系统哨兵 `oral-none`；它不属于随机 trait 池，也不计入 `8:4:1`，并且不能被锁定、重掷或写成普通 trait ID。不得把牙齿或舌头强塞进关闭嘴型。嘴部 edge occlusion 与眼部相同，只来自模板并重放当前骨架表面，不携带固定肤色。

### 7.4 小型附属物与母版结构接口

```ts
type StructuralShapeClass =
  | 'feline-standard'
  | 'cat-tail-long'
  | 'cat-tail-curled'
  | 'dog-tail-curled'

type AttachmentShapeClass =
  | 'ear-horn-small'
  | 'ear-ornament'
  | 'mane-small'
  | 'collar'

type ShapeClass = StructuralShapeClass | AttachmentShapeClass

interface MasterAttachmentInterfaceV1 {
  interfaceId: string
  allowedShapeClasses: AttachmentShapeClass[]
  allowedZone: PngResourceRef
  rearRootStencil: PngResourceRef
  frontRootStencil?: PngResourceRef
  fixedOccluderMaskId: string
}

interface AttachmentTraitBundleV1 extends TraitBundleBaseV1 {
  kind: 'attachment'
  slotId: 'headAppendage' | 'extraAppendage'
  interfaceId: string
  shapeClass: AttachmentShapeClass
  behind: PngResourceRef
  front?: PngResourceRef
}
```

它与历史“视觉插槽”的边界是：接口不接受局部图片、不保存锚点、不计算 transform，也不在运行时求连接。附属物已经在完整母版的最终像素坐标中制作。连接由模板预制的隐藏重叠结构保证，而不是由“相交若干像素”推测：

1. 生产工作台把 `rearRootStencil` 作为不可擦除的固定根注入 `behind`，trait 只能从它向外延伸；
2. 固定根随后被骨架或 occlusion replay 完全遮住；
3. 可见延伸只能在与固定根连通的 `allowedZone` 内制作；
4. 只有接口提供 `frontRootStencil` 时才能提供 `front`，工作台同样把该固定根作为不可擦除内容注入 front；
5. attachment 不能提供自己的 cover、mask、transform 或层级。

大型解剖轮廓不使用该接口：完整尾巴、头型、体型和四肢都属于 `SkeletonFamily`。`cat-tail-long`、`cat-tail-curled` 等 `StructuralShapeClass` 只用于声明完整骨架的语义；它们不是可叠加的尾巴附件。`dog-tail-curled` 可供未来犬类骨架登记，但猫骨架不得声明它。附属 trait 只能使用 `AttachmentShapeClass`，因此也不能把尾形伪装成头饰。枚举中不存在鱼尾、多头或独立肢体形态，这类素材无法通过 schema；多头也没有任何可注册接口。

每个附属 trait 还必须出现在对应骨架的批准白名单中：键为 `(skeletonFamilyId, interfaceId, shapeClass, sealedArtifactSha256)`。四项任一不匹配均拒绝解析。白名单只由一次完整母版视觉批准产生，运行时没有“看起来差不多”的后备匹配。

### 7.5 特效

特效必须是判别联合：

```ts
interface TargetedEffectTraitBundleV1 extends TraitBundleBaseV1 {
  kind: 'targetedEffect'
  slotId: 'effect'
  targetId: string
  layer: PngResourceRef
}

interface AmbientEffectTraitBundleV1 extends TraitBundleBaseV1 {
  kind: 'ambientEffect'
  slotId: 'effect'
  zoneId: 'background' | 'foreground'
  layer: PngResourceRef
}

type TraitBundleV1 =
  | SurfaceTraitBundleV1
  | EyePairTraitBundleV1
  | MouthTraitBundleV1
  | OralDetailTraitBundleV1
  | AttachmentTraitBundleV1
  | TargetedEffectTraitBundleV1
  | AmbientEffectTraitBundleV1
```

- `targetedEffect` 绑定一个已登记的身体语义 slot，例如耳、爪、尾或呼吸；
- `ambientEffect` 只进入固定的背景或前景 effect zone；
- 两类使用不同 schema，不能把 `ambient` 冒充身体 target；
- 特效不能进入 surface、embedded 或 attachment 节点。

## 8. 完整母版上下文制作

每个 trait 的生产流程固定如下：

1. 生产工具根据 `skeletonFamilyId` 加载已批准的中性完整母版。
2. 工具加载对应 slot 的 authoring mask、固定 occluder 和上下文提示；非授权像素在编辑器层不可写。
3. 图像模型或人工编辑始终看到完整生物，但只能改变 slot 允许的区域。
4. 生产工具导出 2048×2048 原位 PNG 或版本化材质操作，同时保存完整上下文预览。
5. 导出物没有 transform、crop rectangle、anchor 或 `zIndex` 字段。
6. `sealTraitBundle` 验证合同后生成不可变 manifest；它不移动、不缩放、不裁剪、不修补素材。

该流程与“先自由生成，再检测位置”不同：位置和可写区域在创作发生前已经被工作台锁死。

## 9. 固定 CompositionGraph

renderer 不接受任意图层数组，只接受经过 catalog 解析的 `ResolvedCompositeV09`。唯一绘制顺序为：

```ts
type CompositionNodeId =
  | 'backgroundEffect'
  | 'attachment.behind'
  | 'skeleton.base'
  | 'surface.bodyColor'
  | 'surface.pattern'
  | 'surface.texture'
  | 'surface.forepawDetail'
  | 'surface.hindpawDetail'
  | 'surface.tailSurface'
  | 'targetedEffect.underlay'
  | 'eyePair.underlay'
  | 'eyePair.content'
  | 'eyePair.edgeOcclusionReplay'
  | 'mouth.back'
  | 'oralDetail'
  | 'mouth.front'
  | 'mouth.edgeOcclusionReplay'
  | 'attachment.front'
  | 'skeleton.attachmentOcclusionReplay'
  | 'targetedEffect.overlay'
  | 'foregroundAmbientEffect'

interface CompositionGraphV1 {
  schemaVersion: 'qmonster-composition-graph-v1'
  orderedNodes: CompositionNodeId[]
  blendMode: 'source-over-premultiplied-srgb'
  transformPolicy: 'identity-only'
}

interface ResolvedCompositeV09 {
  versionTuple: typeof V09_VERSION_TUPLE
  speciesRigId: string
  skeletonFamilyId: string
  assemblyTemplateId: string
  releaseManifestSha256: string
  orderedNodes: Record<CompositionNodeId, ContentResourceRef[]>
  sourceArtifactSha256s: string[]
}
```

`orderedNodes` 必须逐项等于下列冻结序列，不能缺项、重复或插入扩展节点：

```text
01 backgroundEffect
02 attachment.behind
03 skeleton.base
04 surface.bodyColor
05 surface.pattern
06 surface.texture
07 surface.forepawDetail
08 surface.hindpawDetail
09 surface.tailSurface
10 targetedEffect.underlay
11 eyePair.underlay
12 eyePair.content
13 eyePair.edgeOcclusionReplay
14 mouth.back
15 oralDetail
16 mouth.front
17 mouth.edgeOcclusionReplay
18 attachment.front
19 skeleton.attachmentOcclusionReplay
20 targetedEffect.overlay
21 foregroundAmbientEffect
```

其中：

- `skeleton.base` 已包含头、颈、躯干、四肢和完整尾巴，不存在这些结构之间的运行时排序；
- surface 节点只能使用 material operation，不能提交普通自由 alpha 图层；
- renderer 在 surface 节点结束后冻结一份 `materializedSkeletonSurface`；所有 `*OcclusionReplay` 只能从这份图像按批准 mask 重放像素，不能引入中性色或另一套纹理；
- 眼睛边缘由当前脸部材质重放遮住，口腔永远夹在嘴的 back/front 与嘴缘重放之间；
- attachment 根部永远位于骨架或 attachment occlusion replay 后；所有帽子、项圈等实体装饰也必须走 attachment，不存在自由 `accessory` 节点；
- trait manifest 没有 `zIndex`，renderer 也没有动态重排分支；
- 所有 PNG 使用 1:1 单位矩阵绘制，非单位矩阵直接报错。

## 10. 不可变资源与 provenance

路径不属于外部合同。模板、trait 和 catalog 只引用仓库受控资源根中的内容 ID：

```ts
interface PngResourceRef {
  resourceId: string
  sha256: string
  mediaType: 'image/png'
  width: 2048
  height: 2048
}

interface JsonResourceRef {
  resourceId: string
  sha256: string
  mediaType: 'application/qmonster-material-v1+json' | 'application/qmonster-manifest-v1+json'
}

type ContentResourceRef = PngResourceRef | JsonResourceRef

type RuntimeResourceRole =
  | 'materialOperation'
  | 'underlay'
  | 'content'
  | 'mouthBack'
  | 'oralProjection'
  | 'mouthFront'
  | 'attachmentBehind'
  | 'attachmentFront'
  | 'effectLayer'

interface SealedTraitArtifactV1 {
  schemaVersion: 'qmonster-sealed-trait-v1'
  traitId: string
  kind: TraitBundleV1['kind']
  slotId: string
  rarity: 'common' | 'rare' | 'legendary'
  skeletonFamilyId: string
  assemblyTemplateId: string
  assemblyTemplateSha256: string
  neutralMasterSha256: string
  interfaceId?: string
  shapeClass?: AttachmentShapeClass
  authoringInputs: ContentResourceRef[]
  runtimeResources: Partial<Record<RuntimeResourceRole, ContentResourceRef>>
  fullContextPreview: PngResourceRef
  sealerVersion: string
}
```

`SealedTraitArtifactV1` 不包含自己的哈希，避免循环摘要。catalog 通过一个 `JsonResourceRef` 引用规范化序列化后的 manifest，该引用上的 `sha256` 是 manifest 的内容哈希。

资源解析器拒绝绝对路径、`..`、符号链接、junction、网络 URL 和 catalog 根目录外资源。v0.9 生产输入只接受已解码 PNG 和版本化 JSON，不接受运行时 SVG、脚本、外部字体或网络资源。

```ts
interface ReleaseManifestV09 {
  schemaVersion: 'qmonster-release-v1'
  versionTuple: typeof V09_VERSION_TUPLE
  speciesRig: JsonResourceRef
  skeletonPool: JsonResourceRef
  skeletonFamilies: JsonResourceRef[]
  assemblyTemplates: JsonResourceRef[]
  approvals: JsonResourceRef[]
  traitApprovals: JsonResourceRef[]
  traitInventory: JsonResourceRef
  sealedTraits: JsonResourceRef[]
  compositionGraph: JsonResourceRef
  rendererBuildSha256: string
}

interface ActiveReleasePointerV1 {
  schemaVersion: 'qmonster-active-release-v1'
  releaseManifestSha256: string
}
```

所有 JSON 摘要都基于 RFC 8785 JSON Canonicalization Scheme 的 UTF-8 字节；PNG 摘要基于解码后按行排列的 2048×2048 RGBA8 非预乘像素，而不是压缩文件字节。PNG 必须先转换到冻结的 sRGB/直 alpha 解码规范，拒绝动画、多帧、ICC 转换歧义和非 8-bit RGBA。这样不同压缩器不会改变内容身份，而不同像素一定产生不同哈希。

## 11. 批准合同

```ts
interface AssemblyApprovalV1 {
  schemaVersion: 'qmonster-assembly-approval-v1'
  assemblyTemplateId: string
  canonicalTemplateSha256: string
  neutralMasterSha256: string
  materialMapSha256: string
  authoringMaskSetSha256: string
  attachmentInterfaceSetSha256: string
  approvedAttachmentAllowlistSha256: string
  compositionGraphSha256: string
  overlaySha256: string
  approvedBy: string
  approvedAt: string
  approvalRevision: number
  status: 'approved' | 'revoked'
}

interface TraitVisualApprovalV1 {
  schemaVersion: 'qmonster-trait-visual-approval-v1'
  skeletonFamilyId: string
  assemblyTemplateSha256: string
  sealedArtifactSha256: string
  fullContextPreviewSha256: string
  approvedBy: string
  approvedAt: string
  status: 'approved' | 'revoked'
}

interface ApprovedAttachmentAllowlistV1 {
  schemaVersion: 'qmonster-attachment-allowlist-v1'
  entries: Array<{
    skeletonFamilyId: string
    interfaceId: string
    shapeClass: AttachmentShapeClass
    sealedArtifactSha256: string
    traitVisualApprovalSha256: string
  }>
}
```

模板使用稳定键排序、UTF-8 和规范化数值格式序列化后计算 `canonicalTemplateSha256`。模板不引用批准记录；release manifest 分别引用 template 和 approval，批准记录再单向绑定模板哈希，避免循环哈希。

当前项目的信任边界是单用户本地仓库：`approvedBy` 记录明确执行视觉批准的用户标识，批准记录随 Git 提交留痕。若未来允许远程第三方上传素材或多人发布，必须另行增加签名 attestation 和服务端权限设计；该部署模式不在 v0.9 范围内。

每个新增 trait 在其目标完整母版上批准一次；批准记录同时绑定 sealed artifact、完整上下文预览和模板哈希。之后只要这些哈希不变，随机组合不再反复执行主观审核。母版、mask、母版结构接口、`shapeClass` 白名单、CompositionGraph 或模板任一变化都会使批准记录失配，发布器必须失败关闭。主骨架与传说骨架分别拥有自己的模板和批准记录；不存在跨骨架的默认继承。

## 12. 发布门禁

### 12.1 设计合同门禁

- trait schema 必须与 `slotId` 构成判别联合；非法 target 或缺层无法解析。
- 所有资源必须是 2048×2048 原位输出或明确的材质操作。
- manifest 不得出现 transform、anchor、crop、自由 `zIndex` 或任意资源路径。
- 资源、母版、模板、批准记录必须形成完整哈希链。
- surface operation 不得写入非 owner material，也不得增加轮廓外 alpha。
- embedded trait 不得在 authoring zone 外产生 alpha。
- attachment 必须使用 template 已登记的母版结构接口；固定 root stencil 必须保持逐像素不变，所有可见部分必须与对应 root 连通并位于允许区。
- attachment 的 `shapeClass` 必须同时属于全局封闭枚举、当前骨架允许集合、当前接口允许集合，并且 sealed artifact 哈希必须命中批准白名单。
- 完整骨架的形态类只能是当前物种允许的结构形态；鱼尾、多头和独立肢体没有合法枚举值或注册入口。
- mouth 与 oral 的 socket class 必须兼容。
- 发布器不裁剪或修复不合格资产。

### 12.2 完整性门禁

- PNG 必须可解码、尺寸固定、颜色空间固定、alpha 非空且没有额外帧。
- 所有数值必须有限；JSON 数组和资源尺寸设置上限。
- 十二个正式外观槽位必须由独立期望清单证明各自恰好包含普通 8、稀有 4、传说 1，trait ID 唯一且均可达；骨架池另行证明恰好包含一个 base 和一个 legendary family。
- catalog 中的每个 `eyes` trait 必须解析为一个完整成对 bundle，不能缺少 underlay 或 content；左右眼和边缘遮挡区必须来自模板。
- `mouthShape` 必须提供 back/front/oral socket；每个非 `oral-none` 口腔 trait 必须有兼容投影，嘴缘遮挡区必须来自模板。
- 每个 attachment 必须满足 slot 定义的完整层集合。

### 12.3 最终合成门禁

- renderer 绘制调用顺序必须与冻结的 CompositionGraph 完全一致。
- 每个资源只能以单位矩阵绘制一次。
- 最终合成不得出现未登记 alpha 来源。
- creator、catalog report、CLI 和 incubator 对同一 spec 输出像素哈希一致。
- incubator 保存、回读后必须原样保留完整版本元组和三个结构 ID。
- 固定 v0.8 spec 的输出哈希、资产清单哈希和版本路由保持不变。
- 所有失败条件必须有负向测试，验证无 catalog 写入、无 active release 切换和结构化诊断。

测试中的期望 inventory、CompositionGraph 和历史哈希来自冻结的独立 fixture，不能从被测 catalog 自身反向生成。

### 12.4 生产工作台门禁

- 在编辑器 API 层测试 authoring zone 外像素不可写，而不只检查导出结果。
- 删除或改变注入的 root stencil 必须在保存前失败；不得等到发布器再裁剪修复。
- 工作台导出结构中不得出现 anchor、transform、crop 或 `zIndex` 字段。
- 同一输入在两个独立进程中 seal 后必须得到相同 canonical manifest 和像素摘要。
- 负向 fixture 必须覆盖：鱼尾 `shapeClass`、多头资源、猫骨架引用犬尾类、未批准哈希、跨骨架投影、附件自定义层级、缺少左右眼之一、关闭嘴搭配口腔细节。

## 14. 版本迁移与回滚

- v0.8 文件、catalog、source index、注册和固定输出哈希在开始 v0.9 工作前冻结。
- v0.9 不直接引用 v0.8 可变路径。需要继承的配色或语义只作为设计意图重新制作并写入新的内容寻址资源。
- 新 generator 默认读取 `active-release.json`；历史 spec 始终按自身版本元组解析。
- 发布时先完整构建并验证 v0.9，再原子切换 active release。
- 回滚只把 active release 指针切回 v0.8；不删除或覆盖 v0.9，也不改变历史 spec。
- 四个消费入口必须在发布和回滚后分别执行相同 spec 的版本解析与像素一致性测试。

## 15. 固定 seed 用户验收

最终用户批次只在全部自动门禁通过后生成。验收记录拆为两个不可变对象，避免“尚未生成的 manifest 却已经包含输出哈希”的生命周期矛盾：

`AcceptancePlanV1` 在首次运行前创建，记录：

- series ID；
- 十个固定 seed 及顺序；
- 创建时间。

每次针对一个已冻结 release 运行时，创建新的 `AcceptanceAttemptV1`，记录 plan 哈希、attempt ID、release manifest 哈希、renderer 哈希、两个骨架模板及批准 revision、运行状态、每个输出的 spec/PNG 哈希和生成时间。attempt 只在全部输出完成后封存；中断信息写入单独日志，不修改已经封存的 attempt。

相同输入因进程中断而进行的确定性重试不是重抽，但输出哈希必须相同。若用户拒绝批次：

1. 冻结失败批次及其证据；
2. 修改素材或模板并产生新的内容哈希及批准 revision；
3. 继续引用同一个 plan，以同一组 seed 生成新的、可追溯 attempt；
4. 不替换 seed，不从多批结果中挑选最好的一批冒充首次结果。

## 16. 狗与兔扩展

未来 `canine` 和 `lagomorph` 分别提供自己的完整 `SkeletonFamily`、`AssemblyTemplate`、authoring mask、母版结构接口和批准记录。

它们复用通用 schema、固定 CompositionGraph 语义、内容寻址资源、sealer、发布门禁和版本路由；不复用猫的像素坐标、mask、结构接口或运行时图层。全局 `ShapeClass` 可以包含犬类或兔类值，但每个物种和骨架只能启用自己的封闭子集。新增物种必须能在不修改 V1 schema 的情况下通过一个最小合同 fixture。

## 17. 非目标

- 不修改 v0.1–v0.8 的历史视觉结果。
- 不支持多头、鱼尾或自由形态的独立肢体组合。
- 不增加繁育、显隐性基因或市场逻辑。
- 不通过运行时 connector、自动居中、仿射变换或补救裁剪兼容错误资产。
- 不接受第三方远程素材上传或多租户发布；未来若增加，需单独设计身份、授权和签名链。
- 不以生成更多随机样本代替模板和母版结构接口审核。

## 18. 完成定义

只有以下条件全部成立，v0.9 的衔接问题才算从设计层关闭：

1. 用户分别批准主骨架与传说骨架的无眼窝完整母版、所有 authoring mask、母版结构接口、形态白名单和固定 CompositionGraph；批准记录绑定完整模板哈希。
2. 旧的独立结构拼接入口在 v0.9 不可达；所有结构变化只能选择完整 `SkeletonFamily`。
3. 全部 surface、embedded、mouth/oral、attachment 和 effect trait 均由完整母版定域工作台产出，没有运行时位置字段。
4. renderer 只能接受 `ResolvedCompositeV09`，并严格执行冻结层级图和单位矩阵。
5. 十二个正式外观槽位按独立清单满足 `8:4:1`，骨架池包含一个 base 和一个 legendary family；所有正向、负向和历史回归门禁通过。
6. creator、catalog report、CLI 和 incubator 使用相同 active release、catalog 和 renderer，并对同一 spec 得到相同像素哈希。
7. v0.8 固定样本与资产清单保持历史哈希；发布和回滚均不覆盖历史资源。
8. 十个固定 seed 通过一个不可变 plan 和逐 release attempt 生成可追溯验收批次，系统不进行主观重抽。
