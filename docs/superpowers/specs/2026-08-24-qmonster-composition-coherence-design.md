# QMonster Creator 生物组合一致性设计

- 日期：2026-08-24
- 状态：书面规格已批准，进入实施计划
- 基线分支：`feature/qmonster-v0.1`
- 前置规格：`docs/superpowers/specs/2026-08-21-qmonster-creator-design.md`
- 前置加固规格：`docs/superpowers/specs/2026-08-23-qmonster-v0.1-hardening-design.md`
- 触发样例：菌沼主题、种子 `qmonster-v0.1-first-hatch`

## 1. 背景

当前 v0.1 已能稳定选择 14 个视觉槽位并合成透明图，但“单个部件合法”尚不能保证“组合后像一只完整生物”。触发样例同时选中了蘑菇头、三眼、巨口、口腔脊、强表皮和孢子光效；若干部件还以画布中心作为隐式定位。结果虽然没有缺图，却呈现为多个贴片堆叠，身体主质量、面部关系和肢体连接都不够清楚。

本设计在保留 14 个固定特征类型、三主题、三骨架和确定性种子的前提下，增加组合层结构规则、主题预算、视觉强度预算、分层挂点和整只生物验收。目标不是降低怪奇程度，而是让怪奇变化始终依附于一个可辨认的生物结构。

## 2. 已确认的产品决策

| 决策 | 结论 |
| --- | --- |
| 密度目标 | 友好怪奇：允许多眼、多肢与较密装饰，但面部和整体轮廓必须清楚 |
| 主题混合 | 软主题一致：约 70% 视觉特征服务主主题，约 30% 可作为跨主题惊喜 |
| 素材策略 | 选择性返工：保留合格素材，先修挂点、缩放和层级，无法模块化的部件才重新生成 |
| 强特征预算 | 自动生成的每只生物最多两个强特征 |
| 验收对象 | 单件 contact sheet 继续保留，但发布门禁以完整生物组合为准 |

## 3. 目标与非目标

### 3.1 目标

1. 每个自动生成结果都具有单一、清楚的身体主质量和可读面部。
2. 头部、五官、口腔细节和附肢通过明确挂点组成结构，不再依赖画布中心碰巧对齐。
3. 同一主主题下保持约 70/30 的一致与惊喜比例，并避免多个强特征争夺视觉中心。
4. 保持种子复现、槽位锁定、局部重抽、手动选择和孵化器语义投影能力。
5. 用目录机器校验、固定组合回归和连续 20 只人工验收共同阻止“合法但不像生物”的结果进入发布目录。

### 3.2 非目标

- 不减少或合并现有 14 个视觉槽位。
- 不增加自由拖拽、任意缩放、旋转或图层编辑器。
- 不引入实时 3D、骨骼动画或后端服务。
- 不一次重做全部素材；仅处理影响结构与可读性的部件。
- 不用针对单一种子的坐标硬编码代替目录数据和通用规则。

## 4. 总体方案

采用“结构约束 + 软主题评分 + 强特征预算 + 选择性素材返工”的组合方案：

```text
GenerationRequest
  -> CompositionPlan（主题预算、强度预算、保留选择）
  -> generator-core 候选选择
  -> CompositionValidator
  -> MonsterSpec
  -> renderer-canvas 挂点树解析
  -> 分层合成与面部保护
  -> 完整生物预览 / 导出 / 验收证据
```

`generator-core` 决定选什么，`asset-catalog` 描述部件怎样连接以及有多强，`renderer-canvas` 只按目录挂点确定性摆放，`creator-web` 只展示命令结果和结构化诊断。任何包都不得根据图片名称猜测部件含义。

## 5. 结构模型

### 5.1 挂点树

每个非 `none` 的可见部件必须参与下面的挂点层级之一：

```text
bodyFrame（根）
├─ headShape
│  ├─ eyes
│  ├─ mouthShape
│  │  └─ oralDetail
│  └─ headAppendage
├─ arms
├─ legs
├─ tail
├─ extraAppendage
├─ surfaceMaterial
├─ pattern
├─ colorScheme
└─ effect
```

- `bodyFrame` 是唯一结构根，必须提供头部、左右手臂、左右腿、尾部、额外附肢和主体覆盖层所需的挂点。
- `headShape` 连接到身体的 `head` 挂点，并提供眼睛、嘴和头饰挂点以及面部安全区。
- `mouthShape` 提供 `oralDetail` 挂点，牙齿或舌头必须相对于嘴定位。
- 表皮、纹样和配色属于身体覆盖层，可使用与身体同源的标准覆盖挂点，但不得成为第二个身体轮廓。
- 特效可以是环境节点或前景节点；前景节点必须遵守面部保护规则。

渲染器不再把 `socket: null` 的可见部件默认放到画布中心。只有 `bodyFrame` 根节点和显式 `none` 可以没有父挂点。其余缺少挂点、父节点或合法放置配置时均为阻断错误。

### 5.2 一个特征可展开多个渲染节点

一个槽位仍只选择一个 `partId`，但该部件可以包含零个、一个或多个 `renderNodes`：

- `none` 部件包含零个节点。
- 一体式眼睛或嘴通常包含一个节点。
- 双臂、双腿、双翼可包含左右两个节点，分别连接到真实挂点。

每个节点声明素材、父槽位、目标挂点、本地原点、批准缩放与镜像、图层和适用骨架。这样可以在不改变 14 槽配方的情况下，把当前包含整对肢体的画布拆成真正连接身体的左右节点。

### 5.3 部件组合元数据

目录中的部件增加组合元数据，概念结构如下：

```ts
interface PartComposition {
  isNone: boolean
  motifTags: ThemeId[]
  visualIntensity: "quiet" | "strong"
  renderNodes: RenderNodeDefinition[]
  providedSockets?: SocketDefinition[]
  faceSafeZone?: Rect
  occlusionPolicy?: "normal" | "protect-face"
}
```

`providedSockets` 和 `faceSafeZone` 使用部件本地坐标，随批准变换一起转换。一个部件是否为 `none`、是否属于强特征以及属于何种主题，必须由字段明确表达，不从透明像素、ID 或文件名推断。

## 6. 生成规则

### 6.1 先结构、后装饰

完整生成按以下阶段执行：

1. 选择骨架和 `bodyFrame`，建立身体挂点。
2. 选择 `headShape`，建立面部安全区和五官挂点。
3. 选择眼睛、嘴、口腔细节，先保证脸可读。
4. 选择手臂、腿、尾巴和额外附肢。
5. 选择表皮、纹样、配色和特效。
6. 执行组合完整校验，之后才返回可导出的 `MonsterSpec`。

候选必须同时通过骨架兼容、互斥、挂点可解析、主题预算和强度预算。目录必须为每个必需槽位提供至少一个安静候选，为每个可选槽位提供显式 `none`，因此正常自动生成不依赖无限重试或随机回退。

### 6.2 软主题一致

`themeId` 同时是整只生物的主视觉母题。`colorScheme` 继续严格绑定主主题。目录明确声明一组固定的“母题机会槽”；生成器在选择骨架后，根据该骨架可用的母题机会槽数量 `M` 建立确定性预算：

- 至少 `M - floor(M × 0.3)` 个机会槽只从主主题池选择。
- 最多 `floor(M × 0.3)` 个机会槽具备跨主题惊喜资格；具备资格不代表必须选到跨主题部件。
- `none` 是主题中性留白：它不会变成跨主题特征，也不会把未使用的惊喜资格转移给其他槽位。
- 在预算内，候选仍按稀有度、基础权重、主题倍率和联动倍率抽取。
- 某槽没有主主题合法候选时可确定性选用跨主题候选，但必须产生 `COMPOSITION_THEME_FALLBACK` 警告；目录发布校验会把这种覆盖缺口视为失败。

母题机会槽必须由目录字段声明，不从当前随机结果推导；身体根、纯配色遮罩和透明占位不重复占用机会槽。槽位的主题／惊喜资格由 `hash(seed, themeId, rigId, slotId, "motif-plan")` 稳定排序，局部重抽不会重新分配其他槽位的资格。这个口径保证不少于七成的组合机会服务主主题，同时允许留白减少拥挤；它不要求每只生物机械地塞满三成异主题部件。

### 6.3 强特征预算

自动生成结果中 `visualIntensity: "strong"` 的部件总数不得超过两个。以下表现通常应标为强特征：

- 三眼或更多眼睛、明显异位眼睛。
- 大幅超出普通头部比例的头冠或菌盖。
- 巨口、纵向裂口或突出舌头。
- 大型额外附肢、覆盖范围很大的表皮变化或抢眼前景特效。

目录评审决定具体标签，生成器只消费标签。候选选择会扣除已锁定／已保留选择的强度成本；达到上限后只允许安静候选和 `none`。

手动选择和导入旧配方不被静默改写。若用户主动组合出三个以上强特征，系统保留选择并显示 `COMPOSITION_INTENSITY_EXCEEDED` 警告；若该组合还违反挂点或遮挡硬约束，则按相应阻断错误处理。之后重抽任一未锁定槽位时，生成器优先恢复到预算内。

### 6.4 可选槽位留白

`headAppendage`、`tail`、`extraAppendage` 和 `effect` 的 `none` 不再只是兜底项。通过目录权重使正常随机生成中每个可选槽位的 `none` 命中率落在 35%–50%，并用固定种子统计测试验证。留白不计入主题或强度预算。

### 6.5 锁定、手动选择和局部重抽

- 锁定和手动选择仍优先于随机权重，且绝不被静默替换。
- 局部重抽先把其他槽位视为保留选择，只在剩余主题与强度预算内选择目标槽；只有挂点依赖发生变化时才重算现有依赖图中的未锁定下游槽位。
- 更换 `bodyFrame` 或 `headShape` 可能改变挂点和安全区，因此其下游结构槽按依赖图重算。
- 若锁定组合使目标槽无合法候选，返回结构化阻断诊断，不用超预算部件偷偷完成生成。

## 7. 渲染与遮挡

### 7.1 确定性挂点解析

渲染器从 `bodyFrame` 开始解析世界变换，再递归解析头、脸、嘴和附肢节点。每个节点只能使用目录批准的缩放与镜像。解析结果仍按稳定的图层和声明顺序绘制，同一 `MonsterSpec`、目录版本和渲染器版本必须产生相同 RGBA。

### 7.2 图层职责

固定职责从后到前为：

1. 地面阴影与后景环境效果。
2. 后侧附肢。
3. 身体根、表皮、纹样和配色。
4. 前侧肢体。
5. 头部。
6. 眼睛、嘴、口腔细节和头饰。
7. 受面部保护的前景效果。

表皮和纹样必须被身体轮廓遮罩裁切，不能在身体外形成第二轮廓。前景效果若声明 `protect-face`，渲染时从其绘制区域扣除变换后的面部安全区；目录质量门禁还需检查原素材不会把主要视觉重量集中在脸上。

### 7.3 面部可见性

组合渲染后，眼睛和嘴各自至少保留其原始可见 alpha 的 85%。眼睛主体和嘴主体至少 80% 位于 `faceSafeZone` 内。未达到阈值时生成 `COMPOSITION_FACE_OCCLUDED` 或 `COMPOSITION_FACE_OUT_OF_ZONE` 阻断错误，不允许正式图片导出。

## 8. 素材选择性返工

每个现有部件按以下顺序处理：

1. **仅改元数据**：造型本身可用，只需补挂点、原点、缩放、图层、强度和母题标签。
2. **裁切或拆分**：造型可用，但一个画布包含左右肢体或大面积无关内容；拆成多个 `renderNodes`，不改变特征 ID。
3. **重新生成**：透视、光照、轮廓或语义无法通过前两种方式成为模块化部件时，使用同一母体和美术规范重新生成。

第一批必须处理触发样例涉及的部件：

- `legs_mushroom`：优先重做或拆分为真正承重的左右腿脚，不能继续读成叠在脸上的第二个菌盖。
- `arms_long_noodle`：补真实左右手臂挂点并检查与身体轮廓的连接。
- `head_mushroom_cap`：检查尺寸、头部挂点、脸部安全区和强特征标签。
- `surface_soft_scales`：裁切到身体遮罩内，降低与面部争夺。
- `oral_gummy_ridges`：绑定嘴部内部挂点，不独立占据脸部区域。
- `effect_spore_glow`：降低遮挡并启用面部保护。

同时审计 `eyes_triple_pearl` 和 `mouth_wide_grin` 的强特征标签，确保触发样例不会再次同时叠加四个以上的视觉中心。

## 9. 诊断与失败策略

新增诊断至少覆盖：

| 诊断码 | 级别 | 含义 |
| --- | --- | --- |
| `COMPOSITION_SOCKET_MISSING` | error | 非根可见节点没有可解析父挂点 |
| `COMPOSITION_FACE_OUT_OF_ZONE` | error | 眼睛或嘴主要区域不在面部安全区 |
| `COMPOSITION_FACE_OCCLUDED` | error | 合成后主要五官可见面积不足 |
| `COMPOSITION_THEME_FALLBACK` | warning | 因目录覆盖不足被迫使用超出主题预算的候选 |
| `COMPOSITION_INTENSITY_EXCEEDED` | warning | 手动选择或旧配方超过两个强特征 |
| `COMPOSITION_BOUNDS_EXCEEDED` | error | 可见生物超出批准构图边界 |

随机生成、渲染或导入遇到 error 时保留当前编辑状态并禁止正式图片导出；warning 不阻止用户继续编辑或导出。目录发布校验不接受固定验收集中出现上述 warning，因为发布目录应为自动生成提供完整候选覆盖。

## 10. 版本与兼容

- `MonsterSpec.schemaVersion` 保持 `0.1.0`，因为 14 槽配方结构不变。
- 新默认目录使用 `catalogVersion: 0.2.0`，新增必填组合元数据和多节点部件定义。
- 挂点树与面部保护改变像素结果，`rendererVersion` 升为 `0.2.0`。
- 现有 `0.1.0` 目录和素材作为只读历史版本保留；旧 `MonsterSpec` 仅在精确版本仍安装时按旧渲染器语义打开，不自动套用 `0.2.0` 坐标或素材。
- 新生成、局部重抽和手动选择默认只使用 `0.2.0` 目录。
- 像素 golden 的变化属于有意版本升级，必须记录审图证据，不能直接覆盖而不复核。

## 11. 验证策略

### 11.1 单元与属性测试

- 固定种子的结构、母题资格和强度预算完全可复现。
- 自动生成结果最多两个强特征，至少 70% 的母题机会槽被分配为主主题专用，跨主题选择不超出惊喜资格数。
- 可选槽位 `none` 的统计命中率分别处于 35%–50%。
- 局部重抽不改变无依赖槽位，也不重新分配其他槽位的母题资格。
- 锁定导致预算耗尽或挂点冲突时产生预期诊断，不静默替换。
- 每个必需槽位在三主题、三骨架和剩余强度预算为零时仍有合法安静候选。

### 11.2 目录与渲染机器门禁

- 所有非 `none` 可见节点都能沿挂点树解析到 `bodyFrame`。
- 所有头型都提供合法 `faceSafeZone`，所有嘴型都为口腔细节提供挂点。
- 表皮和纹样存在身体裁切遮罩；受保护效果存在合法遮挡策略。
- 眼睛、嘴的安全区占比和最终可见 alpha 达到第 7.3 节阈值。
- 完整生物边界位于 2048 源画布的批准构图区内，1024 输出不裁断肢体。
- 同一引擎中固定组合的解码 RGBA 保持稳定。

### 11.3 完整生物验收

保留单部件 contact sheet 供素材检查，另生成完整组合 contact sheet。发布前按既有固定序列连续生成至少 20 只，覆盖三主题和三骨架；另外强制加入触发样例 `qmonster-v0.1-first-hatch` 作为回归样例。

每只必须同时通过：

- 身体是单一、占主导的质量，头部与身体关系明确。
- 眼睛和嘴在缩小到 256×256 时仍可辨认。
- 非 `none` 的肢体从身体合理区域延伸，不悬浮、不叠在脸上。
- 不超过两个强特征，主题可辨且跨主题成分不超过约三成。
- 表皮、纹样和效果不产生第二身体轮廓，不遮住主要五官。
- 整体保持明亮、圆润、触感明确的友好怪奇风格。

任何一只失败都必须修正目录、规则或素材后，从连续 20 只的第一只重新验收。最终完整组合 contact sheet 交由用户确认。

## 12. 交付顺序

后续实施计划按以下依赖顺序拆分：

1. 扩展目录 Schema、组合元数据和版本注册。
2. 为身体、头、嘴和多节点附肢建立挂点树与验证器。
3. 在生成核心加入主题预算、强度预算和留白分布。
4. 更新渲染器的层级放置、身体裁切和面部保护。
5. 对触发样例素材做首批选择性返工。
6. 更新网页诊断与新默认目录。
7. 增加固定种子、统计、像素和完整组合验收门禁。

在前四步通过测试前，不批量重新生成素材；这样可以先确认新的模块化接口，再把返工素材一次性生产到正确规范。

## 13. 完成定义

只有同时满足以下条件，组合一致性改造才视为完成：

1. 全量类型检查、单元测试、属性测试、目录校验、生产构建和浏览器工作流通过。
2. 新生成结果满足主题、强特征、挂点、面部可见性和构图边界规则。
3. 触发样例不再呈现贴片堆叠，并通过机器门禁和人工视觉复核。
4. 连续 20 只完整生物验收通过，覆盖三主题和三骨架。
5. 用户确认最终完整组合 contact sheet。
6. 旧 `0.1.0` 配方保持精确版本读取能力，新作品使用 `0.2.0` 目录和渲染器。
