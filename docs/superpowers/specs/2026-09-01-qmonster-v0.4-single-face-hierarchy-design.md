# QMonster v0.4 单一脸部与视觉层级设计

- 日期：2026-09-01
- 状态：设计已在会话中批准，等待书面规格复核
- 基线分支：`feature/qmonster-v0.1`
- 前置规格：`docs/superpowers/specs/2026-08-24-qmonster-composition-coherence-design.md`
- 触发批次：`artifacts/acceptance/random-genome-20260901-a`

## 1. 背景与根因

最新随机批次的头部、五官、头身接口和四肢接口已经基本满足结构要求，但多只生物仍缺少唯一、明确的视觉中心。问题不是五官脱离头部，而是非脸部素材产生了脸部语义：

- `surface_soft_scales` 的多排高对比鳞片容易被理解为牙齿；
- `pattern_gentle_stripes` 的厚横向绒带容易被理解为多层嘴唇；
- 两者叠加时会在躯干形成多排“嘴唇 + 牙齿”；
- `effect_bioluminescent_orbs` 的数量和尺寸过大，常与真实脸部争夺视觉中心。

现有系统只验证 `eyes` 和 `mouthShape` 是否位于头部安全区，并用 `visualIntensity` 控制全身强特征数量。它没有验证 `oralDetail` 的脸区归属，也没有单独限制 `surfaceMaterial`、`pattern` 和 `effect` 对脸部注意力的竞争。若干大面积素材仍被标记为 `quiet`，使强度预算失效。

## 2. 已确认的产品决策

| 决策 | 结论 |
| --- | --- |
| 修复方式 | 选择性重做误导性素材，同时增加通用组合约束 |
| 单一脸部范围 | 普通、变异、怪诞模式默认都保持明确脸部；只有显式多头或异位眼变异可以例外 |
| 版本策略 | 新增不可变的目录和渲染版本 `0.4.0`；保留 `0.3.0` 供旧记录恢复 |
| 生成与审核 | 按新规则单次生成素材和最终随机批次；不在过程中进行主观审核—重生成循环，由用户终审 |

## 3. 目标与非目标

### 3.1 目标

1. 自动生成结果具有一个清楚的主脸；显式双头结果具有两套完整且清楚的脸。
2. 表皮、纹样和特效服从身体体积，不在躯干偶然形成眼睛、牙齿、嘴唇或第二张脸。
3. 完整脸组 `eyes + mouthShape + oralDetail` 绑定同一头部脸区并保持可见。
4. 自动生成同时遵守全身强特征预算和非脸部强视觉预算。
5. 新生成使用 `0.4.0`，旧 `0.3.0` 规格和资源保持可恢复、可重绘。
6. 保持 14 个视觉槽位、确定性种子、锁定、重抽、四层基因和孵化器适配能力。

### 3.2 非目标

- 不合并或新增视觉槽位。
- 不重做已合格的头部和五官素材。
- 不用计算机视觉模型判断图片是否“像一张脸”。
- 不自动迁移或覆写旧 `0.3.0` 生物。
- 不在本轮执行反复的主观视觉评审与自动重生成。
- 不因个别随机结果不理想而静默更换 seed。

## 4. 总体方案

采用“版本化素材返工 + 双重强度预算 + 完整脸组校验 + 单次用户终审”：

```text
GenerationRequest
  -> Catalog 0.4.0
  -> CompositionPlan
       - maxStrongFeatures = 2
       - maxStrongNonFacialFeatures = 1
  -> 14-slot deterministic selection
  -> MonsterSpec 0.1.0 + Genome 0.1.0
  -> Renderer 0.4.0
       - structural connector validation
       - eyes / mouthShape / oralDetail face-zone validation
       - explicit mutation face-zone expansion
  -> one generated review batch
  -> pending_user_review
```

`generator-core` 决定允许哪些部件共同出现；`asset-catalog` 提供真实的视觉强度、挂点和版本化资源；`renderer-canvas` 负责脸区、遮挡和结构指标；生成脚本只生成一次证据批次，不代替用户作视觉批准。

## 5. 目录与组合契约

### 5.1 版本

- 新增 `catalogVersion: "0.4.0"` 和 `rendererVersion: "0.4.0"`。
- `MonsterSpec.schemaVersion` 保持 `0.1.0`。
- `MonsterGenome.genomeVersion` 保持 `0.1.0`。
- `0.3.0` 目录、资源、渲染分支和接受证据不得被覆盖。
- 相同 `partId` 可以在 `0.4.0` 中指向新的版本化资源；其身份由 `catalogVersion + partId` 共同解释。

### 5.2 双重强度预算

保留现有：

```text
maxStrongFeatures = 2
```

新增：

```text
maxStrongNonFacialFeatures = 1
nonFacialSlots = [surfaceMaterial, pattern, effect]
```

自动生成时，三个非脸部槽位中最多一个选择 `visualIntensity: "strong"` 的非 `none` 部件。该限制与全身最多两个强特征同时生效。达到任一预算后，后续槽位只能选择 `quiet` 或 `none`。

目录发布前必须根据最终渲染占地和对比度重新审核 `visualIntensity`，不能根据名称或预期语义标记。大面积浮雕、厚横带、大型高亮球体或能改变第一视觉中心的部件必须为 `strong`。

锁定、导入和手动选择继续保留用户明确选择；超过强度预算时产生结构化警告，不静默替换。目录本身不得包含单件就会在躯干产生明确第二张脸的生产素材，因此手动选择不会绕过素材发布门禁。

### 5.3 显式变异

- `mutation_double_head` 必须复制 `headShape`、`eyes`、`mouthShape`、`oralDetail`、`headAppendage` 和对应脸区。
- `aberration_misplaced_eye` 只移动目录明确指定的眼部节点，并声明对应的有效脸区。
- 普通的 `mutation` 或 `aberration` 模式不会自动放宽脸部约束；只有具体 modifier 的显式语义可以增加或移动脸部。

## 6. 素材返工规则

### 6.1 必须返工

1. `surface_soft_scales`
   - 移除整齐多排、朝向一致的高对比白色鳞片；
   - 改为服从身体曲面的稀疏、小尺度或低对比鳞片；
   - 不形成连续牙列。
2. `pattern_gentle_stripes`
   - 移除横贯躯干的厚绒带；
   - 改为贴附身体的平面或低浮雕纹样；
   - 不切断躯干主质量，不形成嘴唇轮廓。
3. `effect_bioluminescent_orbs`
   - 减少球体数量和单体尺寸；
   - 采用不对称外围分布；
   - 避开脸区与胸腹中央识别区。

### 6.2 条件返工

对 `surface_gel_bubbles`、`surface_mushroom_velvet`、`surface_short_fur` 及其余纹样、特效执行统一的面积、对比度和组合预算检查。只有不满足新规则的素材才返工，已合格素材原样进入 `0.4.0`。

### 6.3 通用美术规范

- 表皮是身体材质，不是独立器官；应随身体曲面和体积变化。
- 纹样是贴附或低浮雕信息，不创建第二个轮廓，不横向分割整个身体。
- 特效是外围强调，不包围脸部，不以对称排列模拟眼睛。
- 非脸部素材不得出现高对比、规则重复的眼形、牙形或唇形序列。
- 保持友好、柔软、玩具感的 3D 风格以及透明背景。

素材按上述规范生成一次。生成后可以执行文件可读性、尺寸、透明通道、哈希和目录契约等客观检查，但不会由代理进行“看起来不够好所以再次生成”的创意循环。

## 7. 渲染与诊断

### 7.1 完整脸组指标

`CompositionMetrics` 扩展为分别记录：

- `eyesInsideRatio` / `eyesVisibleRatio`；
- `mouthInsideRatio` / `mouthVisibleRatio`；
- `oralDetailInsideRatio` / `oralDetailVisibleRatio`。

三类素材分别使用目录的 `faceInsideRatio` 和 `faceVisibleRatio` 门槛。显式 `none` 口腔细节不产生失败；非 `none` 口腔细节必须位于由其所属 `headShape` 提供的同一脸区。

新增诊断沿用明确槽位路径：

- `COMPOSITION_FACE_OUT_OF_ZONE`；
- `COMPOSITION_FACE_OCCLUDED`；
- `COMPOSITION_NONFACIAL_INTENSITY_EXCEEDED`。

### 7.2 图层与遮挡

- `effect` 继续使用 `protect-face` 裁剪策略。
- `surfaceMaterial` 和 `pattern` 继续依附身体并位于头部和脸部图层之后，不覆盖真实脸组。
- `oralDetail` 作为 `mouthShape` 子节点，与嘴共同参与脸部可见度计算。
- 双头拥有两个脸区；脸部 alpha 位于任一所属脸区才算有效。

## 8. 测试与证据

### 8.1 自动测试

实施遵循测试驱动：每项行为先加入会针对 `0.3.0` 现状失败的测试，再实现 `0.4.0`。

- 目录和规格解析接受 `0.4.0`，同时继续接受旧版本。
- 版本路由对 `0.4.0` 使用新渲染器，不回退到其他版本。
- 自动选择在普通、变异、怪诞模式下都满足两个强度预算。
- 对每种模式运行 10,000 个确定性种子统计，确认 `maximumStrongFeatures <= 2` 且 `maximumStrongNonFacialFeatures <= 1`。
- 非 `none` 的 `oralDetail` 必须通过脸区内占比和可见度指标。
- 双头复制完整脸组和两个脸区；非显式变异不得增加脸区。
- `0.3.0` 固定规格继续按旧版本加载和渲染。
- 当前 12 个问题 seed 固定保存为 `0.4.0` 回归输入，不静默替换。

### 8.2 单次视觉交付

完成客观自动校验后：

1. 只生成一批新的随机生物；
2. 输出逐只 PNG、完整 `MonsterSpec`、基因、批次清单、哈希和 contact sheet；
3. 批次记录的决定状态为 `pending_user_review`；
4. 代理不自行批准、不剔除坏 seed、不因主观视觉判断重新生成；
5. 用户查看该批次后决定通过、返工或发起下一轮。

这一区分保证自动测试负责契约正确性，用户负责最终美术判断。

## 9. 孵化器兼容

- 孵化器加载器新增 `0.4.0` 目录与渲染器组合。
- 新孵化默认请求 `0.4.0`。
- 旧记录仍按其 `catalogVersion` 和 `rendererVersion` 恢复，不改写版本字段。
- 图片缓存键继续包含目录版本、渲染版本、尺寸、阴影参数和完整规格哈希。
- 对接文档更新版本表、加载示例、部署目录和恢复测试，但不改变 `HatchMonsterResult`、14 槽位或 genome 公共结构。

## 10. 完成标准

- `0.4.0` 目录、资源与渲染路由存在，`0.3.0` 未被修改或覆盖。
- 三个必须返工素材拥有新的版本化资源和可追溯哈希。
- 所有自动测试、类型检查、目录校验、构建和适量端到端测试通过。
- 三种模式的确定性统计满足双重强度预算。
- 完整脸组指标覆盖 `oralDetail` 和显式多头例外。
- 孵化器接入文档包含 `0.4.0` 升级路径。
- 已输出且仅输出一批待用户审核的随机生物证据，未进行主观重生成循环。
